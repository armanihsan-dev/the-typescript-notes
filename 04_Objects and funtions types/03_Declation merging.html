DECLARATION MERGING

MASTERING INTERFACES, NAMESPACES, AND MODULE AUGMENTATION

Part 1: What is Declaration Merging?

Definition

Declaration Merging: TypeScript's ability to automatically combine multiple declarations of the same name into a single definition. When you declare the same interface, namespace, or class multiple times, TypeScript merges them together.

The Magic

// First declaration
interface User {
    name: string;
    age: number;
}

// Second declaration (same name)
interface User {
    email: string;
    isActive: boolean;
}

// TypeScript MERGES them automatically!
// Final User interface = {
//     name: string;
//     age: number;
//     email: string;
//     isActive: boolean;
// }

let user: User = {
    name: "Alice",
    age: 25,
    email: "alice@email.com",
    isActive: true
};

Part 2: Types of Declaration Merging

2.1 Interface Merging (Most Common)

// ✅ Interfaces merge automatically
interface Person {
    name: string;
}

interface Person {
    age: number;
}

interface Person {
    greet(): void;
}

// Final Person = { name: string; age: number; greet(): void }

let person: Person = {
    name: "Alice",
    age: 25,
    greet() {
        console.log(`Hello, I'm ${this.name}`);
    }
};

2.2 Namespace Merging

Namespace merging in TypeScript means two or more declarations with the same namespace name are combined into one. TypeScript uses this when you split a namespace across multiple places, and it joins all the exported members together.

Syntax

namespace MySpace {
  export const a = 1;
}

namespace MySpace {
  export const b = 2;
}

Here:

  • namespace MySpace declares the same namespace name twice.
  • export makes members visible outside that block.
  • TypeScript merges both blocks into one MySpace.

How it works

TypeScript collects declarations with the same name and combines them into one definition. For namespaces, only exported members become part of the merged result; non-exported members stay local to their own block.

Example

namespace User {
  export function getName() {
    return "Arman";
  }
}

namespace User {
  export function getAge() {
    return 25;
  }
}

User.getName();
User.getAge();

After merging, TypeScript treats User as one namespace containing both functions.

When to use it

It is mostly useful in older TypeScript code, library typing, and declaration files. In modern app development, ES modules are usually preferred over namespaces.

// ✅ Namespaces merge
namespace Animals {
    export class Dog {
        bark() {
            console.log("Woof!");
        }
    }
}

namespace Animals {
    export class Cat {
        meow() {
            console.log("Meow!");
        }
    }
}

// Final Animals namespace has BOTH Dog and Cat
const dog = new Animals.Dog();
const cat = new Animals.Cat();
dog.bark();  // Woof!
cat.meow();  // Meow!

Module Augmentation (Global Declaration)

Module augmentation in TypeScript means adding new types to an existing module without changing its original source code. It is commonly used when you want to extend a third-party library or add extra properties/methods to something that already exists.

Syntax

The main syntax is declare global { ... }. Inside that block, you write extra interfaces, types, or method signatures for the existing module.

declare global {
    interface Window {
        myName: string
    }
    interface Array {
        length: number;
        push(...items: T[]): number;
    }

    interface Array {
        last(): T | undefined;  // Add custom method
        first(): T | undefined; // Add custom method
    }

}

// window.myName = "Arman"

// Now all arrays have these methods!
const numbers = [1, 2, 3, 4, 5];
console.log(numbers.last());  // 5
console.log(numbers.first()); // 1

Part 3: Why Declaration Merging is Useful

3.1 Extending Third-Party Libraries

// Problem: You're using Express, but it doesn't have a custom property
// You want to add `user` property to Express Request

// SOLUTION: Declaration merging!

// express.d.ts (your file)
declare global {
    namespace Express {
        interface Request {
            user: {
                id: string;
                name: string;
                email: string;
            };
        }
    }
}

// Now in your code, Request has the user property!
app.get('/profile', (req: Request, res: Response) => {
    const userId = req.user.id;  // ✅ TypeScript knows this exists!
    const userName = req.user.name;  // ✅ TypeScript knows this exists!
});

3.2 Adding Methods to Built-in Objects

// Adding a custom method to String
interface String {
    toTitleCase(): string;
}

// Implementation
String.prototype.toTitleCase = function(): string {
    return this.split(' ')
        .map(word => word[0].toUpperCase() + word.slice(1).toLowerCase())
        .join(' ');
};

// Usage
const name = "john doe";
console.log(name.toTitleCase()); // "John Doe"
// ✅ TypeScript knows about toTitleCase!

3.3 Extending the Window Object

// In your global.d.ts file
interface Window {
    __APP_CONFIG__: {
        apiUrl: string;
        version: string;
        environment: 'development' | 'production';
    };
}

// Now you can use it safely!
window.__APP_CONFIG__ = {
    apiUrl: 'https://api.example.com',
    version: '1.0.0',
    environment: 'development'
};

const apiUrl = window.__APP_CONFIG__.apiUrl;  // ✅ TypeScript knows

Part 4: Real-World Examples

Example 1: Express.js with Custom Properties

// types/express.d.ts
import { User } from '../models/User';

declare global {
    namespace Express {
        interface Request {
            user: User;
            session: {
                id: string;
                data: Record;
            };
        }
    }
}

// In your route handler
app.get('/dashboard', (req: Request, res: Response) => {
    // TypeScript knows these exist now!
    const user = req.user;  // Type: User
    const sessionId = req.session.id;  // Type: string
});
