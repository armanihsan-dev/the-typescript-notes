STRUCTURAL VS NOMINAL TYPING

COMPLETE GUIDE TO HOW TYPESCRIPT EVALUATES TYPE COMPATIBILITY

Part 1: Clear Definitions

Nominal Typing (Also Called "Name-Based Typing")

Definition: Two types are considered compatible only if they have the same name (declaration). Even if two types have identical structure, they are NOT compatible if they have different names.

Key characteristic: The name of the type matters, not its shape.

Structural Typing (Also Called "Duck Typing")

Definition: Two types are considered compatible if they have the same structure (shape). The name of the type doesn't matter; only its properties and their types matter.

Key characteristic: The shape of the type matters, not its name.

Part 3: TypeScript is Structurally Typed

Important

TypeScript uses structural typing by default. This is one of its most distinctive features.

Simple Example

// TypeScript uses STRUCTURAL typing
type Dog = {
    name: string;
    bark(): void;
};

type Cat = {
    name: string;
    meow(): void;
};

// Different types, but compatible if structure matches
let dog: Dog = {
    name: "Rex",
    bark: () => console.log("Woof!")
};

let cat: Cat = {
    name: "Whiskers",
    meow: () => console.log("Meow!")
};

// ✅ Works: Dog and Cat have different names but same structure?
// Wait, they DON'T have the same structure! (bark vs meow)
// Let's try with identical structure:

True Structural Typing Example

type User = {
    id: number;
    name: string;
    email: string;
};

type Customer = {
    id: number;
    name: string;
    email: string;
};

// Different names, but IDENTICAL structure
let user: User = {
    id: 1,
    name: "Alice",
    email: "alice@email.com"
};

// ✅ Works in TypeScript (Structural Typing)
let customer: Customer = user;  // Allowed!
console.log(customer.name); // "Alice"

// This would NEVER work in a nominally typed language like Java

Part 4: Structural Typing in Action

4.1 Extra Properties Are Allowed

// Structural typing: Extra properties are fine
type Person = {
    name: string;
    age: number;
};

// Object has extra property "email"
let person: Person = {
    name: "Alice",
    age: 25,
    email: "alice@email.com"  // ✅ Allowed (extra property)
};

// Function with structural typing
function greet(person: Person): string {
    return `Hello ${person.name}`;
}

// Can pass objects with extra properties
greet({
    name: "Bob",
    age: 30,
    email: "bob@email.com",  // ✅ Allowed
    phone: "123-456-7890"    // ✅ Allowed
});

4.2 Missing Properties Are NOT Allowed

type Person = {
    name: string;
    age: number;
};

// ❌ Missing required property "age"
let person: Person = {
    name: "Alice"
    // Error: Property 'age' is missing
};

// ❌ Missing required property "name"
let person2: Person = {
    age: 25
    // Error: Property 'name' is missing
};

4.3 Subtype Relationship

// In structural typing, having more properties means
// you're a subtype of the simpler type

type Person = {
    name: string;
    age: number;
};

type Employee = {
    name: string;
    age: number;
    employeeId: string;
    department: string;
};

// ✅ Employee is a subtype of Person
let employee: Employee = {
    name: "Alice",
    age: 25,
    employeeId: "EMP001",
    department: "Engineering"
};

// Can assign Employee to Person (more specific to more general)
let person: Person = employee;  // ✅ Allowed

// ❌ Cannot assign Person to Employee (less specific to more specific)
let person2: Person = {
    name: "Bob",
    age: 30
};

let employee2: Employee = person2;
// Error: Property 'employeeId' is missing
