TYPE ALIAS VS INTERFACE

THE ABSOLUTE COMPLETE DIFFERENCE

Part 1: The Core Difference (The "Why")

Aspect Type Alias Interface
Purpose Creates a new name for any type Defines a contract/blueprint for an object
Mental Model "This is what this type looks like" "This is what this object must have"
Philosophy Type aliases are type definitions Interfaces are object shape definitions

Part 2: What Each Can Do (Capabilities Comparison)

2.1 Primitive Types (Type Alias Wins)

// ✅ Type Alias: Can alias ANY type
type UserID = string;
type Age = number;
type IsActive = boolean;
type Status = "pending" | "approved" | "rejected";

// ❌ Interface: Cannot alias primitives
interface UserID extends string {} // ❌ Error: Cannot extend primitive
interface Age extends number {}    // ❌ Error: Cannot extend primitive

2.2 Union Types (Type Alias Wins)

// ✅ Type Alias: Can create union types
type StringOrNumber = string | number;
type Status = "pending" | "approved" | "rejected";
type Pet = Dog | Cat;

// ❌ Interface: Cannot create union types
interface StringOrNumber extends string | number {} // ❌ Error
interface Status extends "pending" | "approved" {}   // ❌ Error

2.3 Tuple Types (Type Alias Wins)

// ✅ Type Alias: Can create tuple types
type Point = [number, number];
type User = [string, number, boolean?];
type RGB = [red: number, green: number, blue: number];

// ❌ Interface: Cannot create tuples
interface Point extends [number, number] {} // ❌ Error
interface User extends [string, number] {}   // ❌ Error

2.4 Object Shapes (Both Work)

// ✅ Type Alias: Works for objects
type Person = {
    name: string;
    age: number;
    greet(): void;
};

// ✅ Interface: Works for objects
interface Person {
    name: string;
    age: number;
    greet(): void;
}

// Both are valid for object shapes
const person1: Person = { name: "Alice", age: 25, greet() {} };

2.5 Extending (Both Work, Different Syntax)

// ✅ Type Alias: Uses intersection (&)
type Animal = { name: string };
type Dog = Animal & { breed: string };
// Dog = { name: string; breed: string }

// ✅ Interface: Uses extends
interface Animal {
    name: string;
}
interface Dog extends Animal {
    breed: string;
}
// Dog = { name: string; breed: string }

// ✅ Extending multiple types
type A = { a: string };
type B = { b: number };
type C = A & B;  // { a: string; b: number }

interface A { a: string; }
interface B { b: number; }
interface C extends A, B { }  // { a: string; b: number }

2.6 Declaration Merging (Interface Wins)

// ✅ Interface: Automatically merges
interface User {
    name: string;
}
interface User {
    age: number;
}
// Final User = { name: string; age: number }

let user: User = {
    name: "Alice",
    age: 25
};

// ❌ Type Alias: Cannot merge
type User = { name: string };
type User = { age: number }; // ❌ Error: Duplicate identifier 'User'

// Declaration merging is useful for extending third-party types
// Example: Adding to Window object
interface Window {
    myCustomProperty: string;
}

// Now you can use it
window.myCustomProperty = "hello"; // ✅ Works

Part 5: Real-World Use Cases

5.1 Library/Framework Design (Use Interface)

Example 1: User Management System

// ✅ Using Interface for public API
interface User {
    id: string;
    name: string;
    email: string;
    createdAt: Date;
}

interface Admin extends User {
    permissions: string[];
    accessLevel: number;
}

// ✅ Using Type Alias for internal states
type UserState = "active" | "inactive" | "suspended";
type UserRole = "admin" | "moderator" | "user";
type UserFilter = { role?: UserRole; status?: UserState };

The Absolute Truth

Summary

Both are powerful. Use Interface for object shapes that will be extended. Use Type Alias for everything else. Both are equally performant at runtime (they don't exist!).
