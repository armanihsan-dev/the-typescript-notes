Complete Guide to Object Literal Types in TypeScript

Part 1: What are Object Literal Types?

Definition

Object Literal Types: A way to define the shape/structure of an object by specifying the types of its properties. They describe what properties an object should have and what types those properties should be.

Syntax

type TypeName = {
    propertyName: propertyType;
    propertyName2: propertyType2;
};

Basic Examples

// 1. Simple object literal type
type Person = {
    name: string;
    age: number;
};

let user: Person = {
    name: "Alice",
    age: 25
};

// 2. With different property types
type Product = {
    id: number;
    name: string;
    price: number;
    inStock: boolean;
};

let laptop: Product = {
    id: 1,
    name: "MacBook Pro",
    price: 1299.99,
    inStock: true
};

// 3. With nested objects
type Address = {
    street: string;
    city: string;
    country: string;
    zipCode: string;
};

type Customer = {
    name: string;
    email: string;
    address: Address;  // Nested object type
};

let customer: Customer = {
    name: "Alice",
    email: "alice@email.com",
    address: {
        street: "123 Main St",
        city: "New York",
        country: "USA",
        zipCode: "10001"
    }
};

Part 2: Property Modifiers in Object Literal Types

1. Optional Properties (?)

Definition: Properties that may or may not exist on the object.

// Optional property using '?'
type User = {
    name: string;
    age: number;
    email?: string;  // Optional property
    phone?: string;  // Optional property
};

// ✅ Valid: All required properties present
let user1: User = {
    name: "Alice",
    age: 25
};

// ✅ Valid: Optional properties can be omitted
let user2: User = {
    name: "Bob",
    age: 30,
    email: "bob@email.com"
};

// ✅ Valid: Both optional properties present
let user3: User = {
    name: "Charlie",
    age: 35,
    email: "charlie@email.com",
    phone: "123-456-7890"
};

// ❌ Error: Required property missing
let user4: User = {
    name: "David"
    // age is missing
};

2. Readonly Properties (readonly)

Definition: Properties that cannot be changed after the object is created.

type Config = {
    readonly id: number;        // Cannot be changed
    readonly createdAt: Date;   // Cannot be changed
    name: string;               // Can be changed
    isActive: boolean;          // Can be changed
};

let config: Config = {
    id: 1,
    createdAt: new Date(),
    name: "App Config",
    isActive: true
};

// ✅ Allowed: Changing non-readonly property
config.name = "New Config";
config.isActive = false;

// ❌ Error: Cannot change readonly property
config.id = 2;  // Error: Cannot assign to 'id' because it is a read-only property
config.createdAt = new Date();  // Error: Cannot assign to 'createdAt' because it is a read-only property

3. Combining Optional and Readonly

type Product = {
    readonly id: number;        // Required & Readonly
    name: string;               // Required & Mutable
    readonly createdAt: Date;   // Required & Readonly
    description?: string;       // Optional & Mutable
    readonly updatedAt?: Date;  // Optional & Readonly
};

let product: Product = {
    id: 1,
    name: "Laptop",
    createdAt: new Date()
};

// ✅ Allowed: Mutable optional property
product.description = "A powerful laptop";

// ❌ Error: Readonly property
product.id = 2;  // Error
product.createdAt = new Date();  // Error
product.updatedAt = new Date();  // Error (readonly)

Part 3: Index Signatures & Record

In TypeScript, Record<Keys, Type> is a built-in utility type used to map a specific set of keys to a consistent value type, effectively creating a structured dictionary or object shape.

Basic Syntax

Record
  • Keys: The allowed keys for the object (must be a string, number, or symbol, or a union of literals).
  • Type: The data type assigned to the values of those keys.

Common Use Cases

1. Simple String or Number Dictionaries

Use this when you have dynamic keys but want to enforce a uniform value type across the entire object.

// A dictionary where any string key must have a number value
const userScores: Record = {
  alice: 95,
  bob: 88,
  charlie: 72
};

Index Signatures Definition

Index Signatures: Allow objects to have dynamic property names while still enforcing type safety.

Syntax

{
    [key: KeyType]: ValueType;
}

Examples

// 1. String index signature
type Dictionary = {
    [key: string]: string;
};

let translations: Dictionary = {
    hello: "hola",
    goodbye: "adiós",
    thankYou: "gracias"
};

// ✅ Adding new properties is allowed
translations.welcome = "bienvenido";

// ❌ Error: Value must be string
translations.number = 42;  // Error: Type 'number' is not assignable to type 'string'

// 2. Number index signature
type NumberArray = {
    [index: number]: string;
};

let fruits: NumberArray = {
    0: "apple",
    1: "banana",
    2: "orange"
};

// 3. Mix of indexed and regular properties
type UserSettings = {
    readonly id: number;
    name: string;
    [key: string]: string | number;  // Additional string properties
};

let settings: UserSettings = {
    id: 1,
    name: "Alice",
    theme: "dark",
    language: "en"
};

// 4. Record utility type (alternative to index signature)
type Dictionary2 = Record;
let translations2: Dictionary2 = {
    hello: "hola",
    goodbye: "adiós"
};

Index Signature Constraints

// Multiple index signatures (restricted)
type Mixed = {
    [key: string]: string | number;  // Value must be string or number
    [key: number]: string;           // Number keys must have string values
};

// This works because string index includes number index value type
let data: Mixed = {
    "name": "Alice",
    "age": 25,
    0: "first"
};

// ❌ Error: String index value must include number index value type
type Invalid = {
    [key: string]: number;    // String values are numbers
    [key: number]: string;    // Number values are strings
    // Error: 'number' index type 'string' is not assignable to 'string' index type 'number'
};

Complete Guide to Interfaces in TypeScript

Part 1: What is an Interface?

Definition

Interface: A contract or blueprint that defines the structure of an object. It specifies what properties and methods an object should have, but does not provide implementation.

Key Characteristics

  • Defines the shape of an object
  • Can be extended by other interfaces
  • Supports declaration merging (multiple declarations combine)
  • Used for type checking at compile time
  • No runtime presence (they're purely TypeScript)

Part 2: Basic Interface Syntax

Syntax

interface InterfaceName {
    propertyName: propertyType;
    propertyName2: propertyType2;
    methodName(): returnType;
}

Basic Examples

// 1. Simple interface
interface Person {
    name: string;
    age: number;
}

let user: Person = {
    name: "Alice",
    age: 25
};

// 2. Interface with methods
interface Greetable {
    name: string;
    greet(): string;
}

let person: Greetable = {
    name: "Bob",
    greet() {
        return `Hello, I'm ${this.name}`;
    }
};

// 3. Interface with multiple property types
interface Product {
    id: number;
    name: string;
    price: number;
    inStock: boolean;
    categories: string[];  // Array
    createdAt: Date;       // Date object
}

let laptop: Product = {
    id: 1,
    name: "MacBook Pro",
    price: 1299.99,
    inStock: true,
    categories: ["Electronics", "Computers"],
    createdAt: new Date()
};

Part 3: Property Modifiers in Interfaces

1. Optional Properties (?)

Definition: Properties that may or may not exist on the implementing object.

interface User {
    id: number;
    name: string;
    email?: string;      // Optional
    phone?: string;      // Optional
    age?: number;        // Optional
}

// ✅ All valid:
let user1: User = { id: 1, name: "Alice" };
let user2: User = { id: 2, name: "Bob", email: "bob@email.com" };
let user3: User = { 
    id: 3, 
    name: "Charlie", 
    email: "charlie@email.com",
    phone: "123-456-7890",
    age: 30
};

// ❌ Error: Required property missing
let user4: User = { id: 1 };  // Error: Property 'name' is missing

Part 4: Function Types in Interfaces

1. Method Syntax

// Method syntax (shorthand)
interface Calculator {
    value: number;
    add(n: number): number;
    subtract(n: number): number;
    multiply(n: number): number;
}

let calc: Calculator = {
    value: 0,
    add(n) {
        this.value += n;
        return this.value;
    },
    subtract(n) {
        this.value -= n;
        return this.value;
    },
    multiply(n) {
        this.value *= n;
        return this.value;
    }
};
