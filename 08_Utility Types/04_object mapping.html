Record<K, T> — Object Mapping Utility Type

🎯 What is Record<K, T>?

Definition:

Record<K, T> creates an object type where:

keys are of type K

values are of type T

It's like a dictionary or map at the type level.

The One-Line Summary

type Record<K, T> = {
    [P in K]: T;
};

Part 1: Basic Syntax

type RecordType = Record<K, T>;

K = the type of keys (string, number, symbol, or union of literals)

T = the type of values

Example 1: String Keys

type NumberDictionary = Record<string, number>;

const scores: NumberDictionary = {
    alice: 100,
    bob: 90,
    charlie: 85
};

// ✅ Access works
console.log(scores.alice); // 100
console.log(scores["bob"]); // 90

Example 2: Union of Literal Keys

type UserRoles = Record<"admin" | "editor" | "viewer", string>;

const roles: UserRoles = {
    admin: "Administrator",
    editor: "Editor",
    viewer: "Viewer"
};

// ✅ All keys required
// ❌ Missing key error:
// const badRoles: UserRoles = {
//     admin: "Administrator",
//     editor: "Editor"
//     // Error: missing viewer
// };

Example 3: Number Keys

type NumberMap = Record<number, string>;

const fruits: NumberMap = {
    0: "apple",
    1: "banana",
    2: "orange"
};

Internal Implementation

type Record<K extends keyof any, T> = {
    [P in K]: T;
};

Why it works:

It's a mapped type.

It iterates over each key in K.

For each key, it assigns type T.

Part 3: Real-World Examples

Example 1: Translation Dictionary

type Language = "en" | "es" | "fr";
type Translation = Record<Language, string>;

const greetings: Translation = {
    en: "Hello",
    es: "Hola",
    fr: "Bonjour"
};

// ✅ Type-safe access
console.log(greetings.en); // "Hello"
console.log(greetings.es); // "Hola"

Example 2: User Roles with Permissions

type Role = "admin" | "editor" | "viewer";

type Permissions = {
    canRead: boolean;
    canWrite: boolean;
    canDelete: boolean;
};

type RolePermissions = Record<Role, Permissions>;

const permissions: RolePermissions = {
    admin: { canRead: true, canWrite: true, canDelete: true },
    editor: { canRead: true, canWrite: true, canDelete: false },
    viewer: { canRead: true, canWrite: false, canDelete: false }
};

Example 3: API Response Cache

type Endpoint = "/users" | "/posts" | "/comments";

type CacheEntry = {
    data: unknown;
    timestamp: number;
};

type ApiCache = Record<Endpoint, CacheEntry>;

const cache: ApiCache = {
    "/users": { data: [], timestamp: Date.now() },
    "/posts": { data: [], timestamp: Date.now() },
    "/comments": { data: [], timestamp: Date.now() }
};

Record vs Index Signatures

Comparison

Feature Record<K, T> Index Signature
Syntax Record<string, number> { [key: string]: number }
Keys Can be specific union Any string/number
Readability More explicit Less explicit
When to use Known keys Unknown keys

Example

// These are equivalent:
type A = Record<string, number>;
type B = { [key: string]: number };

// But Record is better for specific keys:
type Status = "pending" | "success" | "failed";
type StatusMessages = Record<Status, string>;
// Same as:
// {
//     pending: string;
//     success: string;
//     failed: string;
// }

Key Takeaways

Concept Explanation
Record<K, T> Creates object type with keys K and values T
When to use Dictionaries, maps, lookup tables
Specific keys Use union of literals for exact keys
All keys required Unlike index signatures, all keys are required
Internal Built with mapped types
