Property Modifier Utility Types — Complete Guide

🎯 What Are Property Modifier Utility Types?

Definition:

Property modifier utility types are built-in TypeScript types that change the modifiers (optional ? and readonly readonly) on properties of an object type.

They let you:

  • Add or remove the ? (optional) modifier
  • Add or remove the readonly modifier

The Two Utility Types

Utility Type What It Does
Partial<T> Makes all properties optional
Required<T> Makes all properties required
Readonly<T> Makes all properties readonly

┌─────────────────────────────────────────────────────────────────┐
│                    PROPERTY MODIFIERS                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  You can ADD or REMOVE two modifiers:                          │
│                                                                  │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  MODIFIER    ADD          REMOVE                         │   │
│  │  ────────    ───          ──────                         │   │

│                                                                  │
│  Utility types wrap these modifiers:                           │
│  • Partial    → adds ?                                         │
│  • Required   → removes ?                                      │
│  • Readonly   → adds readonly                                  │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

1. 📦 Partial<T> — Make Everything Optional

Definition

Partial<T> makes all properties of T optional.

Syntax

type Partial<T> = {
    [K in keyof T]?: T[K];
};

How It Works

interface User {
    id: number;
    name: string;
    email: string;
}

type PartialUser = Partial<User>;
// {
//     id?: number;
//     name?: string;
//     email?: string;
// }

Step by Step

┌─────────────────────────────────────────────────────────────────┐
│                    HOW Partial WORKS                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  Partial<User>                                                  │
│                                                                  │
│  Step 1: keyof User = "id" | "name" | "email"                  │
│                                                                  │
│  Step 2: For each key, add ? modifier                         │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  id    → id?: number                                    │   │
│  │  name  → name?: string                                  │   │
│  │  email → email?: string                                 │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
│  Result: All properties become optional!                      │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

Example

interface User {
    id: number;
    name: string;
    email: string;
}

// Full object required
const user1: User = {
    id: 1,
    name: "Alice",
    email: "alice@email.com"
};

// Partial object allowed
const user2: Partial<User> = {
    name: "Alice"
}; // ✅ Works! All other properties are optional

const user3: Partial<User> = {}; // ✅ Works! Empty object is valid

Use Case: Update Payloads

function updateUser(id: number, updates: Partial<User>): void {
    // Only update provided fields
}

updateUser(1, { name: "Bob" });          // ✅
updateUser(2, { email: "bob@email.com" }); // ✅
updateUser(3, {});                        // ✅

2. 📦 Required<T> — Make Everything Required

Definition

Required<T> makes all properties of T required (removes ?).

Syntax

type Required<T> = {
    [K in keyof T]-?: T[K];
};

How It Works

interface Config {
    apiUrl?: string;
    timeout?: number;
    retries?: number;
}

type RequiredConfig = Required<Config>;
// {
//     apiUrl: string;
//     timeout: number;
//     retries: number;
// }

Step by Step

┌─────────────────────────────────────────────────────────────────┐
│                    HOW Required WORKS                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  Required<Config>                                               │
│                                                                  │
│  Step 1: keyof Config = "apiUrl" | "timeout" | "retries"       │
│                                                                  │
│  Step 2: For each key, remove ? modifier                       │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  apiUrl?  → apiUrl: string                              │   │
│  │  timeout? → timeout: number                             │   │
│  │  retries? → retries: number                             │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
│  Result: All properties become required!                      │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

Example

interface Config {
    apiUrl?: string;
    timeout?: number;
}

// All optional
const config1: Config = {}; // ✅

// All required
const config2: Required<Config> = {
    apiUrl: "https://api.com",
    timeout: 5000
}; // ✅ Works

// ❌ Error: missing timeout
const config3: Required<Config> = {
    apiUrl: "https://api.com"
}; // ❌ Error: Property 'timeout' is missing

Use Case: After Validation

function processConfig(config: Config): void {
    // After validation, we know all fields exist
    const validated: Required<Config> = {
        apiUrl: config.apiUrl ?? "default",
        timeout: config.timeout ?? 5000
    };
    // Now we can safely use all fields
}

3. 📦 Readonly<T> — Make Everything Readonly

Definition

Readonly<T> makes all properties of T readonly (immutable).

Syntax

type Readonly<T> = {
    readonly [K in keyof T]: T[K];
};

How It Works

interface User {
    id: number;
    name: string;
    email: string;
}

type ReadonlyUser = Readonly<User>;
// {
//     readonly id: number;
//     readonly name: string;
//     readonly email: string;
// }

Step by Step

┌─────────────────────────────────────────────────────────────────┐
│                    HOW Readonly WORKS                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  Readonly<User>                                                 │
│                                                                  │
│  Step 1: keyof User = "id" | "name" | "email"                  │
│                                                                  │
│  Step 2: For each key, add readonly modifier                   │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  id    → readonly id: number                            │   │
│  │  name  → readonly name: string                          │   │
│  │  email → readonly email: string                         │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
│  Result: All properties become readonly!                      │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

Example

interface User {
    id: number;
    name: string;
}

const user: Readonly<User> = {
    id: 1,
    name: "Alice"
};

// ✅ Read allowed
console.log(user.name); // "Alice"

// ❌ Write not allowed
user.name = "Bob"; // Error: Cannot assign to 'name' because it is a read-only property
user.id = 2;       // Error: Cannot assign to 'id' because it is a read-only property

Use Case: Immutable State

type AppState = Readonly<{
    user: User | null;
    posts: Post[];
    loading: boolean;
}>;

const state: AppState = {
    user: null,
    posts: [],
    loading: false
};

// ❌ Can't mutate state directly
state.loading = true; // Error

// ✅ Must create a new state
const newState: AppState = {
    ...state,
    loading: true
};

┌─────────────────────────────────────────────────────────────────┐
│                    INTERNAL IMPLEMENTATIONS                     │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  Partial<T> = {                                                │
│      [K in keyof T]?: T[K]          // ← Add ?                │
│  };                                                             │
│                                                                  │
│  Required<T> = {                                               │
│      [K in keyof T]-?: T[K]         // ← Remove ?             │
│  };                                                             │
│                                                                  │
│  Readonly<T> = {                                               │
│      readonly [K in keyof T]: T[K]  // ← Add readonly         │
│  };                                                             │
│                                                                  │
│  All three use MAPPED TYPES + PROPERTY MODIFIERS.              │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

🎯 Key Takeaways

Concept Explanation
Partial Adds ? to all properties
Required Removes ? from all properties
Readonly Adds readonly to all properties
How they work Built with mapped types + modifiers
When to use Update payloads, validation, immutable state

🧪 Practice Exercises

// 1. Make all properties optional
interface User {
    id: number;
    name: string;
    email: string;
}
type PartialUser = Partial<User>;
// { id?: number; name?: string; email?: string }

// 2. Make all properties required
interface Config {
    apiUrl?: string;
    timeout?: number;
}
type RequiredConfig = Required<Config>;
// { apiUrl: string; timeout: number }

// 3. Make all properties readonly
interface State {
    count: number;
    name: string;
}
type ReadonlyState = Readonly<State>;
// { readonly count: number; readonly name: string }

// 4. Combine with other utility types
type PartialReadonlyUser = Readonly<Partial<User>>;
// { readonly id?: number; readonly name?: string; readonly email?: string }
