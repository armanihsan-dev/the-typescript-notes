Union Utility Types — Simplified

🎯 What Are Union Utility Types?

Definition:

Union utility types are built-in TypeScript types that filter union types. They let you remove, keep, or clean members of a union.

The Core Idea

┌─────────────────────────────────────────────────────────────────┐
│                    UNION UTILITY TYPES                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  A union type is a list of possibilities:                      │
│  "pending" | "success" | "failed" | "cancelled"                │
│                                                                  │
│  Union utility types let you:                                  │
│  • REMOVE some possibilities (Exclude)                         │
│  • KEEP only some possibilities (Extract)                      │
│  • CLEAN nullable values (NonNullable)                         │
│                                                                  │
│  Input Union → Utility Type → New Union                        │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

1. 🚫 Exclude<T, U> — Remove Types

Definition

Exclude<T, U> removes from T any type that is assignable to U.

Syntax

type Result = Exclude<T, U>;

T = the original union

U = the types to remove

How It Works

type Status = "pending" | "success" | "failed" | "cancelled";

type ActiveStatus = Exclude<Status, "cancelled">;
// Result: "pending" | "success" | "failed"

Step by Step

┌─────────────────────────────────────────────────────────────────┐
│                    HOW Exclude WORKS                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  Exclude<"pending" | "success" | "failed" | "cancelled",       │
│          "cancelled">                                          │
│                                                                  │
│  Step 1: Split the union                                       │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  "pending"    → is it "cancelled"? NO → keep "pending"  │   │
│  │  "success"    → is it "cancelled"? NO → keep "success"  │   │
│  │  "failed"     → is it "cancelled"? NO → keep "failed"   │   │
│  │  "cancelled"  → is it "cancelled"? YES → remove it      │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
│  Step 2: Combine what's left                                   │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  "pending" | "success" | "failed"                       │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

Internal Implementation

// Exclude is built with a conditional type
type MyExclude<T, U> = T extends U ? never : T;

Why it works:

  • T extends U ? never : T means: "If T is in U, remove it (never). Otherwise, keep it."
  • Conditional types distribute over unions.
  • never disappears from unions.

Example

// Remove "cancelled" from the status union
type Status = "pending" | "success" | "failed" | "cancelled";
type ActiveStatus = Exclude<Status, "cancelled">;
// ActiveStatus = "pending" | "success" | "failed"

// Now you can't use "cancelled"
let status: ActiveStatus;
status = "success";     // ✅ Works
status = "cancelled";   // ❌ Error

2. 🎯 Extract<T, U> — Keep Only Matching Types

Definition

Extract<T, U> keeps from T only the types that are assignable to U.

Syntax

type Result = Extract<T, U>;

T = the original union

U = the types to keep

How It Works

type Status = "pending" | "success" | "failed" | "cancelled";

type FinalStatus = Extract<Status, "success" | "failed">;
// Result: "success" | "failed"

Step by Step

┌─────────────────────────────────────────────────────────────────┐
│                    HOW Extract WORKS                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  Extract<"pending" | "success" | "failed" | "cancelled",       │
│          "success" | "failed">                                 │
│                                                                  │
│  Step 1: Split the union                                       │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  "pending"    → is it "success" | "failed"? NO → remove  │   │
│  │  "success"    → is it "success" | "failed"? YES → keep   │   │
│  │  "failed"     → is it "success" | "failed"? YES → keep   │   │
│  │  "cancelled"  → is it "success" | "failed"? NO → remove  │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
│  Step 2: Combine what's left                                   │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  "success" | "failed"                                   │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

Internal Implementation

// Extract is built with a conditional type
type MyExtract<T, U> = T extends U ? T : never;

Why it works:

  • T extends U ? T : never means: "If T is in U, keep it. Otherwise, remove it (never)."
  • Conditional types distribute over unions.
  • never disappears from unions.

Example

// Keep only "success" and "failed"
type Status = "pending" | "success" | "failed" | "cancelled";
type FinalStatus = Extract<Status, "success" | "failed">;
// FinalStatus = "success" | "failed"

// Works with string patterns too!
type UserEvent =
    | "user:create"
    | "user:update"
    | "user:delete"
    | "order:create"
    | "order:update"
    | "payment:success"
    | "payment:failed";

type UserOnlyEvents = Extract<UserEvent, `user:${string}`>;
// UserOnlyEvents = "user:create" | "user:update" | "user:delete"

// Works with object types too!
type Response =
    | { type: "success"; data: string }
    | { type: "error"; message: string }
    | { type: "loading" };

type SuccessResponse = Extract<Response, { type: "success" }>;
// SuccessResponse = { type: "success"; data: string }

3. 🧹 NonNullable<T> — Remove null and undefined

Definition

NonNullable<T> removes null and undefined from T.

Syntax

type Result = NonNullable<T>;

How It Works

type UserName = string | null | undefined;

type ValidUserName = NonNullable<UserName>;
// Result: string

Step by Step

┌─────────────────────────────────────────────────────────────────┐
│                    HOW NonNullable WORKS                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  NonNullable<string | null | undefined>                        │
│                                                                  │
│  Step 1: Split the union                                       │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  string     → is it null | undefined? NO → keep string  │   │
│  │  null       → is it null | undefined? YES → remove      │   │
│  │  undefined  → is it null | undefined? YES → remove      │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
│  Step 2: Combine what's left                                   │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  string                                                 │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

Internal Implementation

// NonNullable is built with Exclude
type NonNullable<T> = Exclude<T, null | undefined>;

Why it works:

It's just Exclude that removes null and undefined.

Example

// Remove null and undefined from a name
type UserName = string | null | undefined;
type ValidUserName = NonNullable<UserName>;
// ValidUserName = string

// Now you can't assign null or undefined
let name: ValidUserName;
name = "Anurag";     // ✅ Works
name = null;         // ❌ Error
name = undefined;    // ❌ Error

// Works with complex types too
type User = {
    name: string | null;
    email: string | undefined;
};

type ValidUser = {
    [K in keyof User]: NonNullable<User[K]>;
};
// ValidUser = {
//     name: string;
//     email: string;
// }

📝 Summary Table

Utility Type What It Does Example
Exclude<T, U> Removes matching types Exclude<"a" | "b" | "c", "a"> → "b" | "c"
Extract<T, U> Keeps matching types Extract<"a" | "b" | "c", "a" | "b"> → "a" | "b"
NonNullable<T> Removes null/undefined NonNullable<string | null> → string

🎯 Key Takeaways

Concept Explanation
Exclude Removes types from a union
Extract Keeps only matching types
NonNullable Removes null and undefined
How they work Built with conditional types and distribution
never disappears Removed types become never, which vanishes in unions
When to use Filtering unions, cleaning data, narrowing types

🧪 Practice Exercises

// 1. Remove "cancelled" from status
type Status = "pending" | "success" | "failed" | "cancelled";
type ActiveStatus = Exclude<Status, "cancelled">;
// "pending" | "success" | "failed"

// 2. Keep only "success" and "failed"
type FinalStatus = Extract<Status, "success" | "failed">;
// "success" | "failed"

// 3. Remove null and undefined
type UserName = string | null | undefined;
type ValidName = NonNullable<UserName>;
// string

// 4. Extract user events
type Event = "user:create" | "user:update" | "order:create";
type UserEvents = Extract<Event, `user:${string}`>;
// "user:create" | "user:update"

// 5. Remove specific object types
type Response =
    | { type: "success"; data: string }
    | { type: "error"; message: string }
    | { type: "loading" };
type SuccessOnly = Extract<Response, { type: "success" }>;
// { type: "success"; data: string }
