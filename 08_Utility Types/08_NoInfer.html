TypeScript NoInfer<Type> — Learn It From Zero

Let's understand NoInfer step by step, with simple examples. The key is understanding how TypeScript infers types before learning what NoInfer changes.

1. First, what is type inference?

Type inference means TypeScript figures out a type for you without requiring you to write it explicitly.

For example:

let color = "red";

TypeScript can infer that color is a string.

It can also infer types for generic functions:

function identity<T>(value: T): T {
  return value;
}

identity("hello"); // T is inferred as string
identity(123);     // T is inferred as number

Here, T is a generic type parameter. TypeScript looks at the argument you pass and decides what T should be.

  • Pass "hello" → T becomes string.
  • Pass 123 → T becomes number.

This is useful because you don't need to specify T manually.

Think of NoInfer<T> as a sign that says:

"NoInfer<T> is a built-in utility type (introduced in TypeScript 5.4) that prevents TypeScript from inferring a type parameter from a specific position. It tells the compiler: "This is type T, but don't use this argument to figure out what T is."

The One-Line Summary

function example<T>(value: NoInfer<T>): void {}
// TypeScript won't infer T from 'value'

🧠 The Problem It Solves

The Scenario: Multiple Inference Candidates

When a generic type parameter appears in multiple places in a function signature, TypeScript tries to infer it from all of them. Sometimes this is not what you want.

The FSM Example

declare function createFSM<TState extends string>(config: {
    initial: TState;
    states: TState[];
}): void;

createFSM({
    initial: "not-allowed",
    states: ["open", "closed"]
});

What happens: TypeScript infers TState from both initial and states. So TState becomes "not-allowed" | "open" | "closed", and no error occurs — even though "not-allowed" is not a valid state

The Solution: NoInfer

declare function createFSM<TState extends string>(config: {
    initial: NoInfer<TState>;  // ← Don't infer from here
    states: TState[];           // ← Infer only from here
}): void;

createFSM({
    initial: "not-allowed",  // ❌ Error!
    states: ["open", "closed"]
});

Now TState is inferred only from states ("open" | "closed"), and initial is checked against that type. Since "not-allowed" isn't in the union, TypeScript throws an error.

OR

“Use this value to check the type, but do not use it to decide the type.”

TypeScript normally looks at all generic arguments to figure out what T should be. NoInfer<T> removes one argument from that decision-making process.

Simple analogy

Imagine you are choosing a dress code:

function party<T>(guests: T[], host: NoInfer<T>) {}

guests says: “These people decide the party’s type.”

host says: “This person must already fit the party’s type.”

So if guests are "Ali" | "Sara", the host must be either "Ali" or "Sara".

Without NoInfer, TypeScript might say: “The host is a new kind of person too, so add them to the allowed type.” That is usually not what you want.

Step by step

function register<Role extends string>(
  allowedRoles: Role[],
  selectedRole: NoInfer<Role>,
) {
  return { selectedRole };
}

When you call:

register(["admin", "manager", "worker"], "admin");

TypeScript does this:

Look at allowedRoles.

Infer Role from it:

Role = "admin" | "manager" | "worker"

Look at selectedRole.

Because it is NoInfer<Role>, do not use "admin" to change Role.

Only check whether "admin" fits the already-decided Role.

It does, so the call works.

Why the invalid one fails

register(["admin", "manager", "worker"], "Normal user");

Step by step:

allowedRoles decides:

Role = "admin" | "manager" | "worker"

selectedRole must be one of those roles.

"Normal user" is not one of them.

TypeScript gives an error.

Without NoInfer, TypeScript might infer:

Role = "admin" | "manager" | "worker" | "Normal user"

Then the invalid value would incorrectly be accepted. NoInfer prevents that.

The one-line rule

Put NoInfer<T> on the argument that should follow the type, not the argument that should create the type. 

function example<T>(
  source: T[],          // this decides T
  checked: NoInfer<T>,  // this must match T
) {}

Tiny mental model

allowedRoles: Role[]          // “I define the allowed roles.”
selectedRole: NoInfer<Role>   // “I must be one of those roles.”

So:

register(["admin", "manager"], "admin");       // ✅ admin is allowed
register(["admin", "manager"], "guest");       // ❌ guest was not allowed

NoInfer is simply TypeScript’s way of saying: “Do not let this argument expand the generic type.”
