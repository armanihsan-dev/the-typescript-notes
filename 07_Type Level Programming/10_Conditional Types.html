CONDITIONAL TYPES IN TYPESCRIPT — COMPLETE GUIDE

🎯 What Are Conditional Types?

Definition:

A conditional type is a type that chooses between two types based on a condition. It works like an if-else statement, but at the type level.

The One-Line Summary

type Result = A extends B ? X : Y;
// "If A is assignable to B Or A is a subset of B, then X, otherwise Y"

Mean
If data-type of A is matching B then X, otherwise Y.

The Mental Model

┌─────────────────────────────────────────────────────────────────┐
│                    CONDITIONAL TYPES                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  VALUE LEVEL:              TYPE LEVEL:                          │
│  ─────────────            ────────────                          │
│                                                                  │
│  if (condition) {          type Result = A extends B           │
│      // do X                  ? X                              │
│  } else {                     : Y;                             │
│      // do Y              }                                     │
│  }                                                              │
│                                                                  │
│  Branch at runtime.       Branch at compile time.              │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

Part 1: Basic Syntax

type ConditionalType<T> = T extends SomeType ? TrueType : FalseType;

Syntax Breakdown

type IsString<T> = T extends string ? true : false;
//                    ↑        ↑        ↑       ↑
//                    |        |        |       |
//                    |        |        |       False branch
//                    |        |        True branch
//                    |        Condition
//                    Type parameter

Simple Example

type IsString<T> = T extends string ? true : false;

type A = IsString<"hello">; // true , becuase type of "hello" is string. after passing it's type string to T generic. it's match with condition like
type IsString<string> = string extends string ? true : false;
    
type B = IsString<42>;      // false
type C = IsString<boolean>; // false

Part 2: The extends Keyword

What Does extends Mean?

In a conditional type, A extends B means: "Is A assignable to B?"

What "Assignable" Means

┌─────────────────────────────────────────────────────────────────┐
│                    WHAT "ASSIGNABLE" MEANS                      │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  A extends B means:                                             │
│  "Can a value of type A be used where B is expected?"          │
│                                                                  │
│  Examples:                                                      │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  "hello" extends string  → YES (literal is a string)   │   │
│  │  42 extends number       → YES (literal is a number)   │   │
│  │  string extends number   → NO  (string is not number)  │   │
│  │  "hello" extends "hello" → YES (same type)             │   │
│  │  "hello" extends "world" → NO  (different literals)    │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

More Examples

// Literal extends general type
type A = "hello" extends string ? true : false; // true
type B = 42 extends number ? true : false;      // true
type C = true extends boolean ? true : false;   // true

// General type does NOT extend literal
type D = string extends "hello" ? true : false; // false
type E = number extends 42 ? true : false;      // false

// Object extends object
type F = { name: string } extends object ? true : false; // true
type G = { name: string } extends { name: string } ? true : false; // true
type H = { name: string } extends { name: string; age: number } ? true : false; // false

Part 3: Conditional Types with Generics

Generic Conditional Types

type IsArray<T> = T extends any[] ? true : false;

type A = IsArray<string[]>;  // true
type B = IsArray<number[]>;  // true
type C = IsArray<string>;    // false
type D = IsArray<{ name: string }>; // false

Extracting Types

// Extract the element type of an array
type ElementType<T> = T extends (infer U)[] ? U : never;

type A = ElementType<string[]>;  // string
type B = ElementType<number[]>;  // number
type C = ElementType<{ name: string }[]>; // { name: string }

Return Type Extraction

// Extract return type of a function
type MyReturnType<T> = T extends (...args: any[]) => infer R ? R : never;

function greet(name: string): string {
    return `Hello ${name}`;
}

type GreetReturn = MyReturnType<typeof greet>; // string

infer R tells TypeScript: “If T matches this function shape, figure out its return type and call that type R.”

type MyReturnType<T> =
    T extends (...args: any[]) => infer R
        ? R
        : never;

Read it in parts:

  • T extends (...args: any[]) => ... checks whether T is a function type.
  • infer R asks TypeScript to infer the type in the function’s return position.
  • ? R returns the inferred type if T matched.
  • : never is the fallback if T wasn’t a function.

For typeof greet, TypeScript matches (name: string) => string, infers R as string, and therefore GreetReturn is string.

R is just a chosen name for the inferred type. It could be called something more descriptive:

type MyReturnType<T> =
    T extends (...args: any[]) => infer Return
        ? Return
        : never;

This is a type-level operation only; it doesn’t call the function at runtime.

Part 6: Conditional Types with any

The Special Behavior of any

// 🔥 Conditional types with any return a UNION of both branches

type Test<T> = T extends string ? "yes" : "no";

type A = Test<string>; // "yes"
type B = Test<number>; // "no"
type C = Test<any>;    // "yes" | "no" (BOTH!)

Why any Behaves This Way

┌─────────────────────────────────────────────────────────────────┐
│                    CONDITIONAL TYPES WITH any                   │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  any extends string ?                                             │
│                                                                  │
│  TypeScript can't decide if `any` is a string or not,          │
│  so it returns BOTH branches as a union:                       │
│                                                                  │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  Test<any> = "yes" | "no"                               │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
│  This is because `any` is both assignable to everything        │
│  and not assignable to everything (by design).                 │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

unknown vs any

type Test<T> = T extends string ? "yes" : "no";

// unknown: Behaves like normal
type A = Test<unknown>; // "no"

// any: Returns both branches
type B = Test<any>;     // "yes" | "no"

type L = any extends string ? "YES" : "NO"
type P = unknown extends string ? "YES" : "NO"
type Q = never extends string ? "YES" : "NO" // never is vacuously true , there’s no value of never that could violate the requirement to be a string.

Part 8: infer in Conditional Types

What is infer?

infer lets you declare a type variable inside a conditional type and extract it from the matched type.

type SomeType<T> =
    T extends SomePattern<infer Found>
        ? Found
        : Fallback;

Read it as:

If T matches SomePattern<...>, infer the type in that position and call it Found. Then return Found. Otherwise, return Fallback.

Found is just a name chosen for the inferred type. It’s a type-level placeholder—not a JavaScript variable.

Example: extracting a function’s return type

type MyReturnType<T> =
    T extends (...args: any[]) => infer R
        ? R
        : never;

function greet(name: string): string {
    return `Hello ${name}`;
}

type GreetReturn = MyReturnType<typeof greet>; // string

TypeScript checks whether typeof greet fits this pattern:
(...args: any[]) => infer R

Since greet has type (name: string) => string, TypeScript infers R as string. The true branch returns R, so GreetReturn is string.

You can use a more descriptive name:

type MyReturnType<T> =
    T extends (...args: any[]) => infer Return
        ? Return
        : never;

Example: extracting function parameters

Parameters are represented as a tuple, so you can infer that tuple

type MyParameters<T> =
    T extends (...args: infer Args) => any
        ? Args
        : never;

type GreetParameters = MyParameters<typeof greet>;
// [name: string]

Here, Args is inferred as [name: string].

You can extract both parameters and return type:

type FunctionParts<T> =
    T extends (...args: infer Args) => infer Return
        ? { args: Args; return: Return }
        : never;

type GreetParts = FunctionParts<typeof greet>;
// { args: [name: string]; return: string }

Example: extracting an array’s element type

type ElementType<T> =
    T extends (infer Element)[]
        ? Element
        : never;

type Names = ElementType<string[]>; // string
type Scores = ElementType<number[]>; // number

TypeScript matches string[] against (infer Element)[] and infers Element as string

Example: extracting part of a string type

type GetId<T> =
    T extends `user-${infer Id}`
        ? Id
        : never;

type Id = GetId<"user-42">; // "42"

Template literal types can also contain inference positions:
infer Id captures the part of the string matching that position.

The fallback branch

The : never in the examples defines what happens if the pattern doesn’t match:

type MyReturnType<T> =
    T extends (...args: any[]) => infer R
        ? R
        : never;

type NotAFunction = MyReturnType<string>; // never

string does not match the function pattern, so the conditional uses the fallback.

How this relates to never, any, and unknown

With a concrete type, the conditional picks a branch based on whether it matches:

type Check<T> = T extends string ? "YES" : "NO";

type A = Check<"hello">; // "YES"
type B = Check<number>;  // "NO"

A useful way to remember infer is: match a type’s shape, capture a piece of it, and use that piece in the true branch.

infer means “capture the type that fits here”

In a conditional type, infer lets TypeScript discover part of a type while checking whether the whole type matches a pattern.

type MyReturnType<T> =
    T extends (...args: any[]) => infer R
        ? R
        : never;

Read this as:

If T is a function whose return type can be described by some type R, then return R. Otherwise, return never.

for example

function greet(name: string): string {
    return `Hello ${name}`;
}

type Greeting = MyReturnType<typeof greet>; // string

TypeScript matches typeof greet against the function pattern, sees that its return type is string, and binds R to string. R is just a name you choose; you could call it Return.

NOTE
infer is only valid inside the extends pattern, and the inferred name is available in the true branch (?).

Practical Use Cases

Use Case 1: Type-Safe Validation

type Validate<T> = T extends string ? string :
                   T extends number ? number :
                   T extends boolean ? boolean :
                   never;

function processValue<T>(value: T): Validate<T> {
    return value as Validate<T>;
}

const a = processValue("hello"); // string
const b = processValue(42);      // number

Extract API Response Type

type ApiResponse<T> = T extends { data: infer D } ? D : never;

type UserResponse = { data: { name: string; age: number } };
type User = ApiResponse<UserResponse>;
// User = { name: string; age: number }
