TypeScript Conditional Types

DISTRIBUTIVE CONDITIONAL TYPES — FULLY EXPLAINED

🎯 The Core Concept

Distributive conditional types = when a conditional type is applied to a union, TypeScript splits the union and runs the conditional on each member separately, then combines the results back into a union.

type Check<T> = T extends string ? "Yes" : "No";

Check<string | number>
// becomes: Check<string> | Check<number>
//       = "Yes" | "No"

Part 1: The Key Requirement — "Naked Type Parameter"

What is a "Naked Type Parameter"?

A type parameter is naked when it appears directly on the left side of extends in a conditional type.

// ✅ Naked — T is directly on the left of extends
type Check<T> = T extends string ? "Yes" : "No";

// ❌ Not naked — T is wrapped in a tuple
type Check<T> = [T] extends [string] ? "Yes" : "No";

Only naked type parameters trigger distribution.

Part 2: Distribution in Action

Example 1: Single Type (No Distribution Visible)

type Check<T> = T extends string ? "Yes" : "No";

type A = Check<string>;
// string extends string ? "Yes" : "No"
// = "Yes"

Only one type, so nothing to distribute.

Example 2: Union Type (Distribution Happens)

type Check<T> = T extends string ? "Yes" : "No";

type B = Check<string | number>;

Step by step:

┌─────────────────────────────────────────────────────────────────┐
│                    DISTRIBUTION STEPS                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  Step 1: Split the union                                       │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  Check<string | number>                                 │   │
│  │  → Check<string> | Check<number>                        │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
│  Step 2: Evaluate each separately                              │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  Check<string> → string extends string ? "Yes" : "No"   │   │
│  │                → "Yes"                                  │   │
│  │                                                         │   │
│  │  Check<number> → number extends string ? "Yes" : "No"   │   │
│  │                → "No"                                   │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
│  Step 3: Combine results                                       │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  "Yes" | "No"                                           │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
│  Result: type B = "Yes" | "No"                                 │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

The Transformation

Check<string | number>
// ↓
Check<string> | Check<number>
// ↓
"Yes" | "No"

Part 3: Why Does This Behavior Exist?

Because unions represent multiple possibilities.

string | number
// means: "value can be string OR value can be number"

TypeScript says: "Let me check each possibility separately."

This is very useful because it lets us:

  • Filter union members
  • Remove union members
  • Transform every union member

Part 4: Use Cases

Use Case 1: Filtering a Union (Keep Only Strings)

type OnlyStrings<T> = T extends string ? T : never;

type Result = OnlyStrings<string | number | boolean>;

Distribution:

┌─────────────────────────────────────────────────────────────────┐
│                    FILTERING WITH DISTRIBUTION                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  Step 1: Split                                                │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  OnlyStrings<string> |                                  │   │
│  │  OnlyStrings<number> |                                  │   │
│  │  OnlyStrings<boolean>                                   │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
│  Step 2: Evaluate each                                        │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  string extends string ? string : never  → string       │   │
│  │  number extends string ? number : never  → never        │   │
│  │  boolean extends string ? boolean : never → never       │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
│  Step 3: Combine                                              │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  string | never | never                                 │   │
│  │  = string (never disappears in unions)                  │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
│  Result: string                                                │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

This is how TypeScript filters union types!

Part 5: How to Disable Distribution

The Tuple Trick

// ❌ Distributive (T is naked)
type Check<T> = T extends string ? "Yes" : "No";

// ✅ Non-distributive (T is wrapped)
type Check<T> = [T] extends [string] ? "Yes" : "No";

Why this works:

  • [T] is a tuple containing T
  • [string] is a tuple containing string
  • TypeScript checks the whole tuple at once, not each member

Comparison

// Distributive version
type Check1<T> = T extends string ? "Yes" : "No";
type A = Check1<string | number>; // "Yes" | "No"

// Non-distributive version
type Check2<T> = [T] extends [string] ? "Yes" : "No";
type B = Check2<string | number>; // "No"

Why B is "No"

┌─────────────────────────────────────────────────────────────────┐
│                    NON-DISTRIBUTIVE                             │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  Check2<string | number>                                        │
│                                                                  │
│  [string | number] extends [string] ?                           │
│                                                                  │
│  Is [string | number] assignable to [string]?                   │
│  → NO (string | number is not the same as string)              │
│                                                                  │
│  Result: "No"                                                   │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

Part 6: The Core Rule

┌─────────────────────────────────────────────────────────────────┐
│                    THE CORE RULE                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  DISTRIBUTES:                                                   │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  type Check<T> = T extends string ? "Yes" : "No";       │   │
│  │  // T is NAKED on the left of extends                   │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
│  DOES NOT DISTRIBUTE:                                           │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  type Check<T> = [T] extends [string] ? "Yes" : "No";   │   │
│  │  // T is WRAPPED in a tuple                             │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

Part 7: Final Mental Model

┌─────────────────────────────────────────────────────────────────┐
│                    DISTRIBUTIVE MENTAL MODEL                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  For each member of the union:                                 │
│      run the conditional type separately                       │
│                                                                  │
│  Then combine all results back into a union.                   │
│                                                                  │
│  So this:                                                       │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  Check<string | number | boolean>                       │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
│  Becomes:                                                       │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  Check<string> | Check<number> | Check<boolean>          │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
│  This is why distributive conditional types are so powerful.   │
│  They allow TypeScript to work on union members one by one.    │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
