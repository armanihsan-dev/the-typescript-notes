TypeScript Conditional Types

POSSIBLE OUTCOMES OF A CONDITIONAL TYPE — COMPLETE GUIDE

🎯 What is Meant by "Possible Outcomes"?

Definition:

A possible outcome of a conditional type is any type that can be produced by that conditional type — either the true branch (X), the false branch (Y), or a combination of both.

Think of it like a function: a conditional type takes an input type and returns an output type. The possible outcomes are all the different output types it can return.

The possible outcomes : 5

The 5 Possible Outcomes of Conditional Types — Explained

This file explains something crucial: a conditional type doesn't always resolve immediately. It has 5 possible outcomes depending on how TypeScript evaluates it.

Let me explain each one clearly.

🎯 The Core Syntax

T extends U ? TrueType : FalseType

This says: "If T is assignable to U, then TrueType, otherwise FalseType."

But TypeScript doesn't always pick one side. Here's why.

✅ Outcome 1: True Branch Is Returned

When: The condition is clearly true.

type A = "Hi" extends string ? "Yes" : "No";
// A = "Yes"

Why:

  • "Hi" is a string literal
  • "Hi" is assignable to string → condition is TRUE
  • TypeScript picks the true branch → "Yes"
┌─────────────────────────────────────────────────────────────────┐
│                    TRUE BRANCH                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  "Hi" extends string ?                                          │
│                                                                  │
│  Is "Hi" assignable to string?  → YES                          │
│                                                                  │
│  Result: "Yes"                                                  │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

❌ Outcome 2: False Branch Is Returned

When: The condition is clearly false.

type B = 100 extends string ? "Yes" : "No";
// B = "No"

Why:

  • 100 is a number literal
  • 100 is NOT assignable to string → condition is FALSE
  • TypeScript picks the false branch → "No"
┌─────────────────────────────────────────────────────────────────┐
│                    FALSE BRANCH                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  100 extends string ?                                           │
│                                                                  │
│  Is 100 assignable to string?  → NO                            │
│                                                                  │
│  Result: "No"                                                   │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

🔀 Outcome 3: Both Branches Returned as a Union

When: TypeScript can't decide because the input is any. 

type C = any extends string ? "Yes" : "No";
// C = "Yes" | "No"

Why:

  • any is a special type — it can behave like anything
  • It could be a string → "Yes" is possible
  • It could be a non-string → "No" is possible
  • TypeScript returns BOTH branches as a union
┌─────────────────────────────────────────────────────────────────┐
│                    BOTH BRANCHES (any)                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  any extends string ?                                           │
│                                                                  │
│  Is any assignable to string?                                   │
│  → YES (any can be a string)                                    │
│  → NO  (any can be a non-string)                                │
│                                                                  │
│  TypeScript can't decide → returns BOTH                         │
│                                                                  │
│  Result: "Yes" | "No"                                           │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

Important: This ONLY happens with any. Other types don't do this.

⏳ Outcome 4: Deferred State

When: The condition depends on a generic type parameter that isn't known yet. 

type IsString<T> = T extends string ? "Yes" : "No";

Why:

  • T is a generic type parameter
  • TypeScript doesn't know what T is yet
  • So it defers the decision until T is provided
type A = IsString<string>;  // Now T = string → "Yes"
type B = IsString<number>;  // Now T = number → "No"
┌─────────────────────────────────────────────────────────────────┐
│                    DEFERRED STATE                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  type IsString<T> = T extends string ? "Yes" : "No";           │
│                                                                  │
│  At this point:                                                 │
│  → T is unknown                                                 │
│  → TypeScript can't decide                                      │
│  → Defers the decision                                          │
│                                                                  │
│  When T is provided:                                            │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  IsString<string> → T = string → "Yes"                  │   │
│  │  IsString<number> → T = number → "No"                   │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

Deferred State Inside a Function

function createHandler<T>() {
    type ParamType = T extends string ? string : number;

    return function (value: ParamType) {
        console.log(value);
    };
}

What's happening:

  • T is unknown when createHandler is declared
  • The conditional type T extends string ? string : number is deferred
  • When you call createHandler<string>(), T becomes string
  • Then ParamType becomes string
// When T = string:
const stringHandler = createHandler<string>();
stringHandler("hello"); // ✅ allowed
stringHandler(123);     // ❌ error

// When T = boolean:
const numberHandler = createHandler<boolean>();
numberHandler(123);     // ✅ allowed
numberHandler("hello"); // ❌ error

Key insight: The deferred state resolves when the generic is provided.
