THE KEYOF OPERATOR — COMPLETE GUIDE

🎯 What is keyof?

Definition:

keyof is a TypeScript type operator that takes an object type and produces a union of its property names (as string/number literal types).

OR

The keyof operator is takes a type as input and returns:

a union of all property keys that TypeScript allows you to access on the value of that type using bracket notation syntax without producing a type error.

The One-Line Summary

type Keys = keyof SomeObjectType;
// Keys becomes a union of all property names

Part 1: Basic Syntax

type Keys = keyof SomeType;

Simple Example

type User = {
    name: string;
    age: number;
    email: string;
};

type UserKeys = keyof User;
// UserKeys = "name" | "age" | "email"

Part 2: How It Works

With Interfaces

interface Product {
    id: number;
    name: string;
    price: number;
    inStock: boolean;
}

type ProductKeys = keyof Product;
// "id" | "name" | "price" | "inStock"

With Type Aliases

type Config = {
    apiUrl: string;
    timeout: number;
    retries: number;
};

type ConfigKeys = keyof Config;
// "apiUrl" | "timeout" | "retries"

With Index Signatures

type Dictionary = {
    [key: string]: string;
};

type DictKeys = keyof Dictionary;
// string | number
// (Because index signatures accept both string and number keys)

With Arrays

type Arr = string[];

type ArrKeys = keyof Arr;
// number | "length" | "push" | "pop" | ... (all array methods)

With Tuples

type Tuple = [string, number, boolean];

type TupleKeys = keyof Tuple;
// "0" | "1" | "2" | "length" | "push" | "pop" | ...

Part 3: Real-World Use Cases

Use Case 1: Type-Safe Property Access

function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
    return obj[key];
}

const user = { name: "Alice", age: 25, email: "alice@email.com" };

getProperty(user, "name");  // ✅ "Alice"
getProperty(user, "age");   // ✅ 25
getProperty(user, "email"); // ✅ "alice@email.com"
getProperty(user, "phone"); // ❌ Error: "phone" is not a key of user

keyof with typeof

The Powerful Combination

const user = {
    name: "Alice",
    age: 25,
    email: "alice@email.com"
};

type UserKeys = keyof typeof user;
// "name" | "age" | "email"

// Without typeof:
type UserKeys2 = keyof { name: string; age: number; email: string };
// Same result

keyof with Numbers and Symbols

Numeric Keys

type NumericKeys = {
    0: string;
    1: number;
    2: boolean;
};

type Keys = keyof NumericKeys;
// 0 | 1 | 2 (number literal types)

Symbol Keys

const sym = Symbol("key");

type WithSymbol = {
    [sym]: string;
    name: string;
};

type Keys = keyof WithSymbol;
// typeof sym | "name"

keyof with Union Types

How keyof Handles Unions

type A = { a: string; shared: boolean };
type B = { b: number; shared: boolean };

type Keys = keyof (A | B);
// "shared"
// Only common keys!

// ❌ Not "a" | "b" | "shared"

Why?

┌─────────────────────────────────────────────────────────────────┐
│                    keyof WITH UNIONS                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  A = { a: string; shared: boolean }                             │
│  B = { b: number; shared: boolean }                             │
│                                                                  │
│  A | B means "either A or B"                                    │
│                                                                  │
│  keyof (A | B) means: "what keys are GUARANTEED in both?"       │
│                                                                  │
│  ✅ "shared" exists in both                                     │
│  ❌ "a" only exists in A                                        │
│  ❌ "b" only exists in B                                        │
│                                                                  │
│  Result: "shared"                                               │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

Getting Union of All Keys

// To get ALL keys from both:
type AllKeys = keyof A | keyof B;
// "a" | "shared" | "b"

keyof with Intersection Types

type A = { a: string; shared: boolean };
type B = { b: number; shared: boolean };

type Keys = keyof (A & B);
// "a" | "b" | "shared"
// ALL keys from both!

Why?

│                    keyof WITH INTERSECTIONS                     │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  A & B means "BOTH A and B"                                     │
│                                                                  │
│  keyof (A & B) means: "what keys exist in the combined object?" │
│                                                                  │
│  ✅ "a" from A                                                  │
│  ✅ "b" from B                                                  │
│  ✅ "shared" from both                                          │
│                                                                  │
│  Result: "a" | "b" | "shared"                                   │

📘 The Role & Benefit of keyof in Type-Level Programming

🎯 The Core Answer

keyof is the "reflection" mechanism of type-level programming. It lets you inspect and extract the structure of object types, turning them into unions of keys. Without keyof, you cannot write generic code that operates on object shapes.

In value-level programming, you use Object.keys() to reflect on an object at runtime.
In type-level programming, keyof is Object.keys() for types — but with far more power because it's computed at compile time.

Why keyof Matters at the Type Level

The Problem Without keyof

// ❌ You have to hardcode every key
function getProperty(obj: any, key: string): any {
    return obj[key];
}
// No type safety. Any string allowed. Return type is any.

// ✅ With keyof:
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
    return obj[key];
}
// key must be a real key. Return type is exact.

The Key Insight

keyof turns object types into union types, which can then be transformed, filtered, mapped, and manipulated at the type level.

┌─────────────────────────────────────────────────────────────────┐
│                    keyof AS A TRANSFORMER                       │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  Object Type                  Union of Keys                     │
│  ────────────                 ─────────────                     │
│                                                                  │
│  { name: string;          →   "name" | "age" | "email"         │
│    age: number;                                                 │
│    email: string }                                              │
│                                                                  │
│  keyof CONVERTS a structured type into a flat union.           │
│  Then you can manipulate that union with type-level tools.     │

The Logic Behind <T, K extends keyof T> — Complete Explanation

🎯 The Core Question

You want to understand why this works:

function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
    return obj[key];
}

Let's break down every single piece and the logic behind each.

Part 1: The Two Type Parameters

T — The Object Type

<T, ...>
  • T is a generic type parameter
  • It represents the type of the object you pass in
  • It can be any type

K — The Key Type

<..., K extends keyof T>
  • K is a second generic type parameter
  • It represents the key you want to access
  • It is constrained to be a key of T

Part 2: Breaking Down K extends keyof T

Let's go from right to left:

K extends keyof T

Step 1: T (The Object Type)

// Suppose T = { name: string; age: number; email: string }

Step 2: keyof T (The Keys as a Union)

// keyof { name: string; age: number; email: string }
// = "name" | "age" | "email"

keyof T produces a union of all property names.

Step 3: K extends keyof T (The Constraint)

// K must be a subtype of "name" | "age" | "email"
// So K can be:
//   - "name"
//   - "age"
//   - "email"
//   - "name" | "age"
//   - "name" | "email"
//   - "age" | "email"
//   - "name" | "age" | "email"

K extends keyof T means K must be one of the keys of T.

Part 4: The Return Type T[K]

: T[K]
  • T[K] is an indexed access type
  • It means: "the type of the property at key K in object T"

How It Works

// If T = { name: string; age: number; email: string }

// T["name"] = string
// T["age"] = number
// T["email"] = string

// So:
// T[K] where K = "name" → string
// T[K] where K = "age"  → number
// T[K] where K = "email" → string

Visual

┌─────────────────────────────────────────────────────────────────┐
│                    T[K] LOGIC                                   │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  T = { name: string; age: number; email: string }              │
│                                                                  │
│  K = "name"  →  T[K] = string                                  │
│  K = "age"   →  T[K] = number                                  │
│  K = "email" →  T[K] = string                                  │
│                                                                  │
│  The return type DEPENDS on K.                                 │
│  This is the power of generics!                                │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

Part 7: Why This Is Type-Level Programming

The Compile-Time Logic

function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
    return obj[key];
}

This function does type-level computation:

Step Type-Level Operation
1Extract keys of T with keyof T
2Constrain K to those keys
3Use K to look up value type T[K]
4Link input T, K to output T[K]

This is a type-level function!

┌─────────────────────────────────────────────────────────────────┐
│                    TYPE-LEVEL FUNCTION                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  Input:                    Output:                              │
│  ┌───────────────────┐    ┌───────────────────┐                │
│  │  T (object type)  │    │  T[K] (value type)│                │
│  │  K (key type)     │    │                   │                │
│  └───────────────────┘    └───────────────────┘                │
│                                                                  │
│  The return type is COMPUTED from the input types.             │
│                                                                  │
│  getProperty<User, "name">  →  string                          │
│  getProperty<User, "age">   →  number                          │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

Part 8: The Logic in Plain English

"Give me any object type T, and any key K that belongs to T. I promise to return the exact value type at that key."

  • T = the object you're working with
  • K extends keyof T = the key must be valid
  • T[K] = the return type is the value at that key

Part 9: Multiple Keys

function getProperties<T, K extends keyof T>(obj: T, keys: K[]): T[K][] {
    return keys.map(key => obj[key]);
}

const user = { name: "Alice", age: 25, email: "alice@email.com" };

const values = getProperties(user, ["name", "email"]);
// values = ["Alice", "alice@email.com"]
// Type: (string | string)[] = string[]

// ❌ Invalid:
getProperties(user, ["name", "phone"]); // Error

How It Works

Part 10: Common Misconceptions

Misconception 1: K is a Value

// ❌ Wrong: K is NOT a value
getProperty(user, "name"); // "name" is a VALUE
// But K is a TYPE that represents "name"

Misconception 2: keyof T is Runtime

// ❌ Wrong: keyof T is NOT runtime
// keyof T is computed at COMPILE TIME
// It doesn't exist at runtime

Misconception 3: T[K] is Runtime Access

// ❌ Wrong: T[K] is NOT runtime property access
// T[K] is a TYPE computed at COMPILE TIME
// The actual access `obj[key]` is runtime

Concept Meaning Example

🎯 Key Takeaways

Concept Explanation
Two parameters T for object, K for key
Constraint K extends keyof T restricts K
Return type T[K] is computed from T and K
Type-level function Links input types to output type
Compile-time All of this happens at compile time

The One-Sentence Answer

<T, K extends keyof T> means: "T is any object type, K is any key of T, and the return type is the value type at that key — computed entirely at compile time."
