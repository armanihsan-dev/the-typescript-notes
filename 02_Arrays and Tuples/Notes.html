Part 1: Array Typing - Fundamentals

1. What is an Array Type?

Definition: An array type in TypeScript specifies what type of elements an array can contain. This ensures type safety when adding, removing, or accessing array elements.

2. Syntax for Declaring Array Types

There are two syntaxes for declaring array types:

// Syntax 1: Type[] - (Recommended, more common)
let numbers: number[] = [1, 2, 3];
let names: string[] = ["Alice", "Bob"];
let isValid: boolean[] = [true, false];

// Syntax 2: Array - (Generic syntax)
let numbers2: Array = [1, 2, 3];
let names2: Array = ["Alice", "Bob"];
let isValid2: Array = [true, false];
Best Practice

Use Type[] syntax as it's more common and readable.

3. Array Types with Mixed Elements

// Union types: Array can contain multiple types
let mixed: (string | number)[] = ["Hello", 42, "World", 100];
// Same as:
let mixed2: Array = ["Hello", 42, "World", 100];

// Union with objects
type User = { name: string; age: number };
type Admin = { name: string; isAdmin: boolean };

let people: (User | Admin)[] = [
    { name: "Alice", age: 25 },
    { name: "Bob", isAdmin: true }
];

4. Nested Arrays (Arrays of Arrays)

// 2D Array: Array of arrays
let matrix: number[][] = [
    [1, 2, 3],
    [4, 5, 6],
    [7, 8, 9]
];

// Same as:
let matrix2: Array> = [
    [1, 2, 3],
    [4, 5, 6]
];

// 3D Array
let cube: number[][][] = [
    [[1, 2], [3, 4]],
    [[5, 6], [7, 8]]
];

5. Empty Arrays

// ❌ Wrong: TypeScript infers as 'any[]'
let data = [];  // Type: any[]

// ✅ Correct: Explicitly type the array
let data: string[] = [];
data.push("Hello");  // ✅ Works
data.push(42);       // ❌ Error: number not assignable to string

// ✅ Or initialize with values
let data = ["Hello"];  // TypeScript infers: string[]
data.push("World");    // ✅ Works
data.push(42);         // ❌ Error

Part 2: Working with Array Methods

1. map() - Transform Each Element

Definition: Creates a new array by applying a function to each element of the original array.

How map() Affects Types:

// Example 1: Mapping to same type
let numbers: number[] = [1, 2, 3, 4, 5];
let doubled: number[] = numbers.map(n => n * 2);
// Result: [2, 4, 6, 8, 10]
// Type: number[] (same as input)

// Example 2: Mapping to different type
let numbers2: number[] = [1, 2, 3, 4, 5];
let strings: string[] = numbers2.map(n => `Number: ${n}`);
// Result: ["Number: 1", "Number: 2", "Number: 3", "Number: 4", "Number: 5"]
// Type: string[] (different from input!)

// Example 3: Mapping objects
type User = { name: string; age: number };
type UserNames = { fullName: string };

let users: User[] = [
    { name: "Alice", age: 25 },
    { name: "Bob", age: 30 }
];

let names: UserNames[] = users.map(user => ({
    fullName: user.name
}));
// Type: UserNames[]

TypeScript's Type Inference with map():

// TypeScript automatically infers the return type
let numbers = [1, 2, 3];
let result = numbers.map(n => n * 2);  // TypeScript infers: number[]
let result2 = numbers.map(n => n.toString());  // TypeScript infers: string[]
Best Practice

Explicitly type the callback parameter:

// ❌ Avoid: Implicit any
let numbers = [1, 2, 3];
let result = numbers.map(n => n * 2);

// ✅ Prefer: Explicit parameter type
let numbers: number[] = [1, 2, 3];
let result = numbers.map((n: number) => n * 2);

2. filter() - Filter Elements

Definition: Creates a new array containing only elements that pass a test.

How filter() Affects Types:

// Basic filtering (same type)
let numbers: number[] = [1, 2, 3, 4, 5, 6];
let evenNumbers: number[] = numbers.filter(n => n % 2 === 0);
// Result: [2, 4, 6]
// Type: number[] (same as input)

// Filtering with objects
type User = { name: string; age: number };
let users: User[] = [
    { name: "Alice", age: 25 },
    { name: "Bob", age: 17 },
    { name: "Charlie", age: 30 }
];

let adults: User[] = users.filter(user => user.age >= 18);
// Type: User[] (same as input)

// Filtering union types (Type Narrowing!)
type Dog = { type: "dog"; bark(): void };
type Cat = { type: "cat"; meow(): void };

let animals: (Dog | Cat)[] = [
    { type: "dog", bark: () => console.log("Woof") },
    { type: "cat", meow: () => console.log("Meow") }
];

// TypeScript narrows the type automatically!
let dogs = animals.filter(animal => animal.type === "dog");
// TypeScript knows: dogs is Dog[]
// Because filter removes all Cat elements

Type Narrowing with filter():

// Example: Filtering out null/undefined
type OptionalString = string | null | undefined;

let items: OptionalString[] = ["Hello", null, "World", undefined, "!"];

// ❌ Without filter, type remains OptionalString[]
let withoutFilter: OptionalString[] = items;
// Type: (string | null | undefined)[]

// ✅ With filter, TypeScript narrows the type
let strings = items.filter((item): item is string => item !== null && item !== undefined);
// Type: string[] (null and undefined are removed!)

// ✅ Using a type guard function
function isString(value: any): value is string {
    return typeof value === "string";
}

let strings2 = items.filter(isString);
// Type: string[]
Best Practice

Use filter with type guards for type narrowing:

type User = { name: string; age: number };
type ApiResponse = User | { error: string };

let responses: ApiResponse[] = [
    { name: "Alice", age: 25 },
    { error: "Not found" },
    { name: "Bob", age: 30 }
];

// Type guard
function isUser(response: ApiResponse): response is User {
    return "name" in response && "age" in response;
}

// Now TypeScript knows successful is User[]
let successful = responses.filter(isUser);
// Type: User[]

3. reduce() - Reduce to Single Value

Definition: Applies a function against an accumulator and each element to reduce the array to a single value.

How reduce() Affects Types:

// Basic reduce: Sum numbers
let numbers: number[] = [1, 2, 3, 4, 5];
let sum: number = numbers.reduce((acc, curr) => acc + curr, 0);
// Result: 15
// Type: number (initial value was number)

// Reduce to string
let sumString: string = numbers.reduce((acc, curr) => acc + curr.toString(), "Sum: ");
// Result: "Sum: 12345"
// Type: string

// Reduce to object
type UserStats = { total: number; count: number };
let ages: number[] = [25, 30, 35, 40];

let stats: UserStats = ages.reduce(
    (acc, age) => ({
        total: acc.total + age,
        count: acc.count + 1
    }),
    { total: 0, count: 0 }
);
// Type: UserStats

// Reduce with objects
type Product = { name: string; price: number };
let products: Product[] = [
    { name: "Laptop", price: 1000 },
    { name: "Mouse", price: 50 },
    { name: "Keyboard", price: 100 }
];

let totalPrice: number = products.reduce((sum, product) => sum + product.price, 0);
// Result: 1150
// Type: number
Best Practice

Always provide initial value and explicit return type:

// ❌ Avoid: Missing initial value (can cause type issues)
let numbers = [1, 2, 3];
let result = numbers.reduce((acc, curr) => acc + curr);
// TypeScript infers type, but might be ambiguous

// ✅ Prefer: Always provide initial value
let result: number = numbers.reduce((acc: number, curr: number) => acc + curr, 0);

// ✅ Prefer: Explicitly type the accumulator
type Result = { sum: number; count: number };
let stats: Result = numbers.reduce(
    (acc, curr) => ({
        sum: acc.sum + curr,
        count: acc.count + 1
    }),
    { sum: 0, count: 0 }
);

Part 4: Tuples

1. What are Tuples?

Definition: A tuple is an array with a fixed length and each element can have a different type.

Key characteristics:

  • Fixed length (number of elements is known)
  • Each position has a specific type
  • Order matters

2. Tuple Syntax

// Basic tuple syntax
let person: [string, number] = ["Alice", 25];
// First element must be string, second must be number

// Tuple with more elements
let user: [string, number, boolean] = ["Alice", 25, true];

// Tuple with mixed types
let data: [number, string, boolean] = [42, "Hello", true];

// Empty tuple
let empty: [] = [];

// Type inference in tuples
let tuple = ["Alice", 25] as const;  // Type: readonly ["Alice", 25]
// or
let tuple2: [string, number] = ["Alice", 25];

3. Accessing Tuple Elements

let person: [string, number] = ["Alice", 25];

// Access by index
let name: string = person[0];  // "Alice"
let age: number = person[1];   // 25

// Destructuring
let [name2, age2] = person;
// name2: string, age2: number

// ❌ Accessing out of bounds
let invalid = person[2];  // Error: Tuple type '[string, number]' of length '2' has no element at index '2'

4. Optional Tuple Elements

// Optional elements using '?'
type User = [string, number, boolean?];
// Third element is optional

let user1: User = ["Alice", 25];        // ✅ Valid
let user2: User = ["Alice", 25, true];  // ✅ Valid
// let user3: User = ["Alice"];         // ❌ Error: Missing second element

// Optional elements must be at the end
type Data = [string, number?, boolean?];  // ✅ Valid
// type Data2 = [string?, number];       // ❌ Invalid: optional can't be before required

5. Tuple Labeling (for documentation)

// Labeled tuple elements
type Person = [name: string, age: number, isActive?: boolean];

let user: Person = ["Alice", 25, true];
// Labels appear in IDE for better documentation

type Point = [x: number, y: number];
let point: Point = [10, 20];

6. Rest Elements in Tuples

// Rest elements allow variable number of elements of the same type
type StringAndNumbers = [string, ...number[]];
// First element is string, rest are numbers

let data1: StringAndNumbers = ["Hello", 1, 2, 3, 4];  // ✅ Valid
let data2: StringAndNumbers = ["Hello"];              // ✅ Valid
let data3: StringAndNumbers = [1, 2, 3];              // ❌ Error: First must be string

// Multiple rest elements
type Mixed = [string, ...number[], boolean];
let data4: Mixed = ["Hello", 1, 2, 3, true];  // ✅ Valid
let data5: Mixed = ["Hello", true];           // ✅ Valid (no numbers)

When to Use Tuples vs Arrays

Use Case Tuples Arrays
Fixed length✅ Yes❌ No
Different types per position✅ Yes❌ Same type only
CSV row data✅ Yes❌ No
Function returns multiple values✅ Yes❌ No
List of similar items❌ No✅ Yes
Collection of same type❌ No✅ Yes
Best Practices for Tuples: 
// ✅ DO: Use tuples for fixed-length structured data
type Coordinates = [x: number, y: number];
type HttpResponse = [status: number, data: any];

// ✅ DO: Use label for clarity
type Person = [name: string, age: number];

// ✅ DO: Use tuples for function return types
function getPerson(): [string, number] {
    return ["Alice", 25];
}

Part 5: Readonly Arrays and Tuples

1. Readonly Arrays

Definition: An array that cannot be modified after creation. No push, pop, splice, or other mutation methods.

// Syntax 1: readonly modifier
let numbers: readonly number[] = [1, 2, 3];
numbers.push(4);     // ❌ Error: Property 'push' does not exist on type 'readonly number[]'
numbers[0] = 10;     // ❌ Error: Cannot assign to '0' because it is a read-only property

// Syntax 2: ReadonlyArray type
let numbers2: ReadonlyArray = [1, 2, 3];
numbers2.push(4);    // ❌ Error
numbers2[0] = 10;    // ❌ Error

// Syntax 3: as const (readonly literal)
let numbers3 = [1, 2, 3] as const;
numbers3.push(4);    // ❌ Error
numbers3[0] = 10;    // ❌ Error

Use Cases for Readonly Arrays:

// 1. Configuration (shouldn't be modified)
const CONFIG_VALUES: readonly string[] = ["development", "production"];

// 2. Function parameters (promise not to modify)
function processItems(items: readonly number[]): number {
    // We can read but not modify
    return items.reduce((sum, n) => sum + n, 0);
}

// 3. Constant data
const MONTHS: readonly string[] = [
    "January", "February", "March", "April",
    "May", "June", "July", "August",
    "September", "October", "November", "December"
];

Converting Between Readonly and Mutable:

// Mutable to readonly
let mutable: number[] = [1, 2, 3];
let readonly: readonly number[] = mutable;  // ✅ Valid (widening)

// Readonly to mutable (requires copy)
let readonly: readonly number[] = [1, 2, 3];
let mutable: number[] = [...readonly];  // ✅ Valid (creates copy)
// or
let mutable2: number[] = readonly.slice();  // ✅ Valid

2. Readonly Tuples

// Readonly tuple syntax
let point: readonly [number, number] = [10, 20];
point[0] = 15;     // ❌ Error: Cannot assign to '0' because it is a read-only property

// Readonly tuple with labels
type Person = readonly [name: string, age: number];
let person: Person = ["Alice", 25];
person[0] = "Bob";  // ❌ Error

// Readonly tuple with rest
type Data = readonly [string, ...number[]];
let data: Data = ["Hello", 1, 2, 3];
data[0] = "Hi";     // ❌ Error
data.push(4);       // ❌ Error

3. as const for Readonly

// The 'as const' assertion makes everything readonly and literal

// Without as const
let colors = ["Red", "Green", "Blue"];
// Type: string[]

// With as const
let colors2 = ["Red", "Green", "Blue"] as const;
// Type: readonly ["Red", "Green", "Blue"] (literal tuple)

colors2[0] = "Purple";  // ❌ Error
colors2.push("Yellow"); // ❌ Error

// Use with objects
let config = {
    server: {
        port: 3000,
        host: "localhost"
    }
} as const;

config.server.port = 4000;  // ❌ Error: Cannot assign to 'port' because it is a read-only property

Part 6: Best Practices Summary

Arrays:

// ✅ DO: Use consistent array syntax
let items: string[] = [];  // Prefer this
// let items: Array = [];  // Also valid

// ✅ DO: Initialize arrays with correct type
let strings: string[] = [];
// ❌ DON'T: let strings = [];  // TypeScript infers any[]

// ✅ DO: Use type guards with filter
let strings = data.filter((item): item is string => typeof item === "string");

// ✅ DO: Explicitly type reduce accumulators
let sum = numbers.reduce((acc, curr) => acc + curr, 0);

// ✅ DO: Use readonly for immutable data
function process(items: readonly number[]): number {
    return items.reduce((a, b) => a + b, 0);
}

Tuples:

// ✅ DO: Use tuples for fixed-length data
type Point = [x: number, y: number];

// ✅ DO: Use labels for clarity
type Person = [name: string, age: number];

// ✅ DO: Use readonly for immutable tuples
type Config = readonly [key: string, value: string];

// ❌ AVOID: Tuples for more than 3-4 elements
type Complex = [string, number, boolean, string, number, boolean];  // Bad

// ✅ BETTER: Use interface for complex structures
interface Complex {
    name: string;
    id: number;
    isActive: boolean;
    // ...
}
