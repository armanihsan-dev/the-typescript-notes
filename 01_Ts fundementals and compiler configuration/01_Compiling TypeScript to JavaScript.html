UNDERSTANDING HOW TYPESCRIPT CODE BECOMES EXECUTABLE JAVASCRIPT

1. What is Compile Time & Runtime?

Compile Time

Definition: The phase when source code (the actual code wrote in a programming language e.g. ts code) is processed by a compiler before execution.

What happens during compile time:

  • Syntax analysis – Checking if code follows language grammar rules
  • Type checking – Verifying type consistency (in TypeScript)
  • Semantic analysis – Checking for logical errors (unused variables, unreachable code)
  • Code generation – Transforming source code into target code (e.g., TS → JS)
  • Optimization – Improving code performance where possible

When compile time occurs:

  • When you manually run tsc command
  • When your build tool runs the compiler
  • When your IDE runs the compiler in the background
Compile Time Facts

Who receives errors: The developer only. End users never see these errors.

Result of an error: No output code is generated. The compilation process stops or produces incomplete output.

Runtime

Definition: The phase when compiled/transpiled code is actually executing in a runtime environment (browser, Node.js, Deno, etc.).

What happens during runtime:

  • Memory allocation – Variables get actual memory addresses
  • Execution – Instructions are executed by the CPU/JavaScript engine
  • I/O operations – Reading/writing files, network requests, user interactions
  • Dynamic errors – Errors that couldn't be caught at compile time (network failures, out-of-memory, type coercion issues in JavaScript)

When runtime occurs:

  • When you run node app.js in terminal
  • When a user visits your website in a browser
  • When a server receives an HTTP request
Runtime Facts

Who receives errors: End users (if unhandled) or developers through error logs.

Result of an error: Program crashes, throws exception, or behaves unexpectedly.

Key Differences

Aspect Compile Time Runtime
When Before execution During execution
Who sees errors Developer only End users (via crashes/bugs)
Error types Syntax, type mismatches, undeclared variables Memory issues, network failures, invalid user input
Cost Developer time (fixed before deployment) Production downtime, user frustration
Examples TS2363 (invalid arithmetic), missing semicolons Cannot read property 'x' of undefined, 500 Internal Server Error

2. What is a Compiler and What is the TypeScript Compiler?

Compiler

Definition: A program that translates source code written in one programming language into another language (usually machine code or another high-level language).

Key functions of a compiler:

  • Lexical analysis – Breaks code into tokens
  • Parsing – Builds an Abstract Syntax Tree (AST)
  • Semantic analysis – Checks types, scopes, and declarations
  • Intermediate code generation – Creates an internal representation
  • Optimization – Improves the intermediate code
  • Code generation – Produces the final output code

TypeScript Compiler (tsc)

Definition: The official compiler for TypeScript, published as the typescript npm package. It transforms TypeScript (.ts) files into JavaScript (.js) files.

3. How to Setup TypeScript Compiler and Compile TypeScript to JavaScript

Step-by-Step Setup:

# Step 1: Initialize npm project (if not already)
npm init -y

# Step 2: Install TypeScript as dev dependency
npm install --save-dev typescript

# Step 3: Create a TypeScript file (app.ts)
# Write your TypeScript code here

# Step 4: Compile to JavaScript
npx tsc app.ts

# This creates: app.js (JavaScript version)
# If you have tsconfig.json, just run:
npx tsc

Complete Example:

File: app.ts

const name: string = "Arman";
const age: number = 25;
console.log(`Name: ${name}, Age: ${age}`);

Compile Command:

npx tsc app.ts

Output: app.js

const name = "Arman";
const age = 25;
console.log(`Name: ${name}, Age: ${age}`);

Run the Output:

node app.js
# Output: Name: Arman, Age: 25

4. Does TypeScript Really Compile? Or Does It Transpile?

Both terms apply, but here's the technical distinction:

Compilation

Definition: Translating source code from a higher-level language to a lower-level language (e.g., C → Assembly, Java → Bytecode).

  • Significant abstraction level change
  • Output is closer to machine code
  • Often involves optimization
  • Runtime performance improves

Transpilation

Definition: Translating source code from one high-level language to another high-level language at similar abstraction level.

  • Similar abstraction level
  • Output is still human-readable
  • Preserves runtime behavior
  • Language features transform to equivalent features in target language

So What Does TypeScript Do?

TypeScript is BOTH a compiler AND a transpiler:

Aspect Classification Explanation
Type checking ✅ Compiler Performs semantic analysis, type validation, and error reporting like a traditional compiler
Output ✅ Transpiler Produces JavaScript (same abstraction level as TypeScript) rather than machine code
Official term "Compiler" The TypeScript team officially calls it a compiler (tsc = TypeScript Compiler)
Technical accuracy "Transpiler" Since input and output are both high-level languages, it's technically transpilation
Conclusion

You can use either term correctly. In practice:
• When talking about type checking: It's a compiler
• When talking about output generation: It's a transpiler
• When talking to other developers: Both terms are accepted

5. What Do These Flags Mean?

--noEmit

Definition: Tells the compiler to perform type checking but NOT generate any output files (.js, .d.ts, .map, etc.)

Use cases:

  • Running TypeScript only for type checking (like a linter)
  • In CI/CD pipelines where you want to validate types without building
  • When you're using a separate bundler (like Webpack) that handles compilation

Example:

# Validates types but produces NO .js files
npx tsc --noEmit
# Common in package.json scripts:
"scripts": {
  "type-check": "tsc --noEmit",
  "build": "tsc"
}

Visual:

┌──────────────────────────────────────────────────────────────┐
│                     tsc --noEmit                           │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  Input:  *.ts files                                        │
│  ↓                                                          │
│  ✅ Type checking (all errors reported)                    │
│  ↓                                                          │
│  ❌ NO output files generated                              │
│                                                              │
│  Result: Types are validated, no code is produced         │
│                                                              │
└──────────────────────────────────────────────────────────────┘

--noEmitOnError

Definition: Prevents the compiler from generating output files if any type errors exist.

Default behavior without flag:

# Even with errors, .js files are still created
tsc app.ts

Result: You get .js files even though types are wrong. These .js files might behave incorrectly at runtime.

With --noEmitOnError: 

# If ANY errors exist, NO .js files are created
tsc --noEmitOnError app.ts

Result: If there are type errors, compilation fails completely and no output is generated.

Comparison Table

Flag What it does When to use
--noEmit No output ever, even if code is perfect CI type-checking, linting
--noEmitOnError Output only if code has zero errors Production builds to prevent shipping broken code

Practical Example

Code with error (app.ts):

const num: number = 5;
num = "hello";  // ❌ Type error

Without flags:

tsc app.ts
app.ts:2:1 - error TS2322: Type 'string' is not assignable to type 'number'.
  num = "hello";

Found 1 error.

app.js is still created!  ← Problem: Broken code is generated

With --noEmitOnError: 

tsc --noEmitOnError app.ts
app.ts:2:1 - error TS2322: Type 'string' is not assignable to type 'number'.
  num = "hello";

Found 1 error.

No output files created.  ← Good: Prevent shipping broken code

With --noEmit: 

tsc --noEmit app.ts
app.ts:2:1 - error TS2322: Type 'string' is not assignable to type 'number'.
  num = "hello";

Found 1 error.

No output files created.  ← Type checking ONLY

Complete Command Reference

# Install TypeScript
npm install -D typescript

# Compile a single file (creates app.js)
npx tsc app.ts

# Compile with configuration file
npx tsc

# Type check without emitting files
npx tsc --noEmit

# Only emit if no errors
npx tsc --noEmitOnError

# Combine both (common in CI)
npx tsc --noEmit --noEmitOnError

# Watch mode (auto-recompile on changes)
npx tsc --watch

# With custom tsconfig
npx tsc -p tsconfig.build.json
