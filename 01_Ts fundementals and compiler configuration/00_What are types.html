UNDERSTANDING TYPES, EXECUTION, AND ERROR HANDLING

1. What Are Types?

Types are a way to describe what kind of data a variable can hold and what operations can be performed on it.

Simple Analogy:

┌─────────────────────────────────────────────────────────┐
│  Real World Analogy                                    │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  A "cup" is a type that can hold liquid                │
│  - You can pour water into it ✅                        │
│  - You can drink from it ✅                             │
│  - You can't put a brick in it ❌ (wrong type!)        │
│                                                         │
│  A "number" type can hold numeric values               │
│  - You can add it ✅                                    │
│  - You can multiply it ✅                               │
│  - You can't subtract a string from it ❌              │
│                                                         │
└─────────────────────────────────────────────────────────┘

In Programming:

// Without types (JavaScript) - Anything goes
let x = 5;        // x is a number
x = "hello";      // Now x is a string - No error!

// With types (TypeScript) - Strict rules
let x: number = 5;    // x MUST always be a number
x = "hello";          // ❌ Error: Type 'string' is not assignable to type 'number'

Types act as constraints that prevent you from making mistakes.

3. How Does Node.js Execute TypeScript?

IMPORTANT

Node.js CANNOT execute TypeScript directly!

The Reality:

┌────────────────────────────────────────────────────────────────┐
│                                                               │
│   Your TypeScript Code (.ts)                                  │
│   ┌─────────────────────────────────────────┐                │
│   │ const num: number = 5;                  │                │
│   │ console.log(num);                       │                │
│   └─────────────────────────────────────────┘                │
│                    │                                          │
│                    ▼                                          │
│   TypeScript Compiler (tsc)                                   │
│   ┌─────────────────────────────────────────┐                │
│   │ Removes all types                       │                │
│   │ Converts to JavaScript (.js)            │                │
│   └─────────────────────────────────────────┘                │
│                    │                                          │
│                    ▼                                          │
│   JavaScript Code (.js)                                       │
│   ┌─────────────────────────────────────────┐                │
│   │ const num = 5;                         │                │
│   │ console.log(num);                      │                │
│   └─────────────────────────────────────────┘                │
│                    │                                          │
│                    ▼                                          │
│   Node.js Executes JavaScript                                │
│   ┌─────────────────────────────────────────┐                │
│   │ node app.js                            │                │
│   └─────────────────────────────────────────┘                │
│                                                               │
└────────────────────────────────────────────────────────────────┘

Two Ways to "Run" TypeScript:

Method 1: Transpile First (Manual)

# Step 1: Compile TypeScript to JavaScript
tsc app.ts          # Creates app.js

# Step 2: Run JavaScript with Node
node app.js         # Executes the compiled JS

Method 2: Use a Runtime (tsx / ts-node)

# These tools compile on-the-fly
npx tsx app.ts      # Compiles and runs in one step
# OR
npx ts-node app.ts  # Compiles and runs in one step

But remember: They're still compiling to JavaScript first, just doing it automatically!

4. Syntax of Adding Types to Variables

Basic Syntax:

// 1. Type annotation after colon
let variableName: Type = value;

// Examples:
let name: string = "Arman";
let age: number = 25;
let isStudent: boolean = true;
let hobbies: string[] = ["coding", "reading"];
let person: { name: string; age: number } = { name: "Arman", age: 25 };

Different Ways to Add Types:

// 1. Explicit type declaration
let x: string = "hello";

// 2. Type inference (TypeScript guesses)
let y = "hello";  // TypeScript infers y is string

// 3. Type assertion (tell TypeScript "trust me")
let z = "hello" as string;
// example : data is coming from frontend to backend api. and you are telling ts that trust me it's type looks like this :
const {name,email, password} = req.body as {name:string,email:string,password:string}

// 4. Function parameters & return types
function greet(name: string): string {
    return "Hello " + name;
}

// 5. Array types
let numbers: number[] = [1, 2, 3];
let numbers2: Array = [1, 2, 3];  // Generic syntax

// 6. Union types (multiple possibilities)
let id: string | number = "ABC123";
id = 123;  // Valid!

5. Why Does Node.js 24+ Execute This, But Browser Doesn't?

The Code:

const num: number = 5;
console.log(typeof num);  // Should print "number"

Why Node.js Works:

Node.js does NOT execute TypeScript either! Here's what's happening:

┌────────────────────────────────────────────────────────────────┐
│ Actually, you're NOT running TypeScript in Node.js!          │
│                                                               │
│ The code you're seeing is either:                            │
│                                                               │
│ 1. Transpiled to JavaScript FIRST                            │
│    ┌────────────────────────────────────────────┐            │
│    │ Original: const num: number = 5;          │            │
│    │ Transpiled: const num = 5;                │            │
│    └────────────────────────────────────────────┘            │
│                                                               │
│ 2. OR you're using tsx/ts-node (still transpiles)            │
│                                                               │
│ 3. OR you're running in a special environment                │
│    (like Deno that has built-in TS support)                  │
│                                                               │
└────────────────────────────────────────────────────────────────┘

Why the Browser Fails:

const num: number = 5;
console.log(typeof num);
// ❌ Uncaught SyntaxError: Missing initializer in const declaration

The browser only understands JavaScript, not TypeScript syntax. It sees : number and gets confused because:

  • The colon : is invalid JavaScript syntax (except in object literals)
  • The browser's JavaScript parser throws an error before executing anything
  • It thinks const num: number is trying to be const num with a label or something

Visual Comparison:

┌─────────────────────────────────────────────────────────────────┐
│ JavaScript (What browsers understand)                         │
├─────────────────────────────────────────────────────────────────┤
│ const num = 5;        ✅ Valid                               │
│ const num: number = 5; ❌ Invalid - colon not allowed here!   │
│                                                                │
│ In JavaScript, `:` is used for:                               │
│ - Object properties: { name: "Arman" }                       │
│ - Ternary operator: x ? y : z                                │
│ - Labeled statements: label: for(...)                        │
│ But NOT for type annotations!                                 │
└─────────────────────────────────────────────────────────────────┘

6. "Running TS Directly" vs "Compiling First" - Explained

Method A: Compile First (Traditional)

Step 1: Write app.ts
Step 2: tsc app.ts → creates app.js
Step 3: node app.js

┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   app.ts    │────►│   tsc       │────►│   app.js    │────►│ node app.js
│ (Types)     │     │ (Compiler)  │     │ (No types)  │
└─────────────┘     └─────────────┘     └─────────────┘
     ▲                                       │
     │                                       │
     └─── You write this                     └─── Node executes this

Pros:

  • Fast execution (no compiling at runtime)
  • Can optimize the output
  • Works everywhere

Cons:

  • Need to run tsc every time you change code
  • Extra step in development

Method B: Direct Execution (tsx / ts-node)

Step 1: Write app.ts
Step 2: tsx app.ts → compiles and runs in memory

┌─────────────┐     ┌─────────────────────────────────────┐
│   app.ts    │────►│ tsx (compiles in memory, executes) │
│ (Types)     │     └─────────────────────────────────────┘
└─────────────┘                 │
     ▲                          │
     │                          │
     └─── You write this        └─── Output appears instantly

Pros:

  • One command to run
  • Faster development loop
  • No intermediate .js files

Cons:

  • Slower startup (compiling takes time)
  • Uses more memory

Comparison Table:

Aspect Compile First Direct Execution
Commandtsc && node app.jstsx app.ts
Files created.js filesNone
Startup speed⚡ Fast (JS only)🐢 Slower (compiles first)
Production ready✅ Yes⚠️ Usually not
DebuggingEasier with source mapsSlightly harder
Memory usageLowerHigher

How Both Are Executed:

┌─────────────────────────────────────────────────────────────────────┐
│ Both methods follow the same pipeline:                            │
│                                                                    │
│  ┌────────────┐    ┌─────────────┐    ┌─────────────┐           │
│  │   .ts File  │───►│   Compile   │───►│   .js File  │───► Node  │
│  └────────────┘    └─────────────┘    └─────────────┘           │
│                                                                    │
│  The only difference is:                                          │
│  - Method A: Saves the .js file to disk                          │
│  - Method B: Keeps the .js in memory (doesn't save)              │
│                                                                    │
└─────────────────────────────────────────────────────────────────────┘

7. Purpose of diagnosticMessages.json GitHub Repo

GitHub link: diagnosticMessages.json

What It Is:

This file contains ALL error messages TypeScript can throw, with unique codes.

Structure:

{
  "Cannot find name '{0}'.": {
    "code": 2304,
    "category": "error"
  },
  "Property '{0}' does not exist on type '{1}'.": {
    "code": 2339,
    "category": "error"
  }
}

Why It Exists:

┌────────────────────────────────────────────────────────────────┐
│ This file serves as the SOURCE OF TRUTH for all TS errors   │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│  1. Translation support:                                      │
│     - The same error can be shown in 40+ languages!          │
│     - "Cannot find name" → "找不到名称" (Chinese)            │
│                                                                │
│  2. Consistency:                                               │
│     - Every error has a unique number                         │
│     - You can Google "TS2304" and find help                  │
│                                                                │
│  3. Tooling:                                                   │
│     - VS Code uses these codes to show hints                 │
│     - ESLint plugins reference these codes                    │
│     - The TS compiler reads this file                         │
│                                                                │
│  4. Developer experience:                                      │
│     - Quick fixes can target specific codes                   │
│     - Error filtering possible                                 │
│                                                                │
└────────────────────────────────────────────────────────────────┘

What the Error 2363 Means:

Your error:

The right-hand side of an arithmetic operation must be of type 'any', 'number', 'bigint' or an enum type.ts(2363)

TS2363 specifically means "Invalid operand in arithmetic operation."

8. Why Does "hi" in number - "hi" Show Error 2363?

The Code:

const number = 5;
number - "hi"  // ❌ Error TS2363

Why This Error?

In TypeScript, the - operator requires both sides to be numbers:

┌────────────────────────────────────────────────────────────────┐
│ TypeScript's Rule:                                           │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│   Valid operands for `-`:                                     │
│   • number - number    ✅                                    │
│   • number - any       ✅ (any disables type checking)      │
│   • number - bigint    ✅                                    │
│   • number - enum      ✅ (enums are numbers behind scenes) │
│                                                                │
│   Invalid operands for `-`:                                   │
│   • number - string    ❌  ← YOUR CASE!                     │
│   • number - boolean   ❌                                    │
│   • number - object    ❌                                    │
│                                                                │
└────────────────────────────────────────────────────────────────┘

What's Actually Happening:

const number = 5;    // TypeScript infers: number
number - "hi";       // "hi" is string, not allowed!

// Even though JavaScript would do:
// 5 - "hi" → NaN (Not a Number)

// TypeScript catches this BEFORE runtime!
// It says: "This might be a mistake, let me warn you"

The Error Message Decoded:

"The right-hand side of an arithmetic operation 
 must be of type 'any', 'number', 'bigint' or an enum type"
 
 ↑                                                           ↑
 |                                                           |
 └── The thing on the right of `-`                          └── These are the only allowed types
     (which is "hi")                                          (string is NOT in this list)

Visual Explanation:

           number - "hi"
           ▲       ▲
           │       │
    ┌──────┘       └──────┐
    │                     │
    ✅ Allowed type      ❌ Not allowed!
    (number)             (string)
    
    TypeScript says: 
    "I can only do math with numbers, not with text!"

9. How Does // @ts-check Help Type Checking in JavaScript?

The Magic Comment:

// @ts-check

const num = 5;
num = "hello";  // ❌ VS Code will show error!

How It Works:

┌────────────────────────────────────────────────────────────────┐
│ Without @ts-check:                                           │
├────────────────────────────────────────────────────────────────┤
│ const num = 5;                                               │
│ num = "hello";     // No error shown!                        │
│ // VS Code treats it as plain JavaScript                    │
└────────────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────────────┐
│ With @ts-check:                                              │
├────────────────────────────────────────────────────────────────┤
│ // @ts-check                                                  │
│ const num = 5;                                               │
│ num = "hello";    // ❌ Type 'string' is not assignable to   │
│                   //    type 'number'                        │
│ // VS Code runs TypeScript's type checker on JS!            │
└────────────────────────────────────────────────────────────────┘

The Complete Picture:

// @ts-check

// 1. Type inference works
const name = "Arman";  // Inferred as string
name = 5;              // ❌ Error: number not assignable to string

// 2. Parameter types inferred
function greet(name) {  // name inferred as any (loose)
    return "Hello " + name;
}
greet(42);  // ✅ Works (but might be wrong)

// 3. JSDoc can add explicit types
/**
 * @param {string} name
 * @returns {string}
 */
function greet2(name) {
    return "Hello " + name;
}
greet2(42);  // ❌ Error: number not assignable to string

// 4. Object types checked
const user = {
    name: "Arman",
    age: 25
};
user.age = "twenty-five";  // ❌ Error: string not assignable to number

How JavaScript Uses TypeScript Behind the Scenes:

┌─────────────────────────────────────────────────────────────────┐
│ The Complete Picture                                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. You write JavaScript with // @ts-check                     │
│  2. VS Code sees the comment                                   │
│  3. VS Code sends the file to tsserver                        │
│  4. tsserver parses it using TypeScript's parser              │
│  5. TypeScript's type checker runs on JavaScript!             │
│  6. Errors are sent back to VS Code                           │
│  7. You see red squiggly lines                                │
│                                                                 │
│  This works because:                                           │
│  - Every valid JS is valid TS                                 │
│  - TypeScript can infer types from plain JS                   │
│  - JSDoc provides explicit type info                          │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
