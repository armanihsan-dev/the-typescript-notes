Part 1: The Problem (Without Generics)

What Most Developers Do

// ❌ Without generics: Type safety is lost
async function fetchData(url: string): Promise {
    const response = await fetch(url);
    return response.json();
}

// Usage:
const user = await fetchData("/api/users/1");
console.log(user.name); // TypeScript doesn't know 'name' exists!
console.log(user.email); // TypeScript doesn't know 'email' exists!
// ❌ No autocomplete
// ❌ No type checking
// ❌ Bugs can slip through

The Problem Explained

Issue Why It's Bad
Return type is any TypeScript can't help you
No autocomplete You have to remember property names
No type checking Typos won't be caught
Hard to refactor Changes break silently

Part 2: The Solution (With Generics)

The Complete Code

// 1. Define the API response structure
interface ApiResponse {
    status: number;
    data: T;
    message: string;
}

// 2. Generic API client
async function apiClient(url: string): Promise<ApiResponse> {
    const response = await fetch(url);
    const data = await response.json();
    
    return {
        status: response.status,
        data: data as T,
        message: response.statusText
    };
}

// 3. Define your data types
interface User {
    id: number;
    name: string;
    email: string;
}

interface Product {
    id: number;
    name: string;
    price: number;
}

// 4. Usage
async function getUsers() {
    const response = await apiClient("/api/users");
    // response.data is User[]
    console.log(response.data[0].name); // ✅ Type-safe!
    return response.data;
}

async function getProducts() {
    const response = await apiClient("/api/products");
    // response.data is Product[]
    console.log(response.data[0].price); // ✅ Type-safe!
    return response.data;
}

Part 3: Breaking Down the Syntax

The Generic API Client

async function apiClient(url: string): Promise<ApiResponse>  {
//                   ↑
//                   |
//          Generic type parameter T

    const response = await fetch(url);
    const data = await response.json();
    
    return {
        status: response.status,
        data: data as T,  // ← T is used here
        message: response.statusText
    };
}

Part 4: Step-by-Step Execution

Step 1: Define Your Types

// You define what the API returns
interface User {
    id: number;
    name: string;
    email: string;
}

Step 2: Call the API Client

const response = await apiClient("/api/users");
//               ↑              ↑
//               |              |
//               T = User[]   API endpoint

Step 3: TypeScript Infers the Types

// TypeScript now knows:
// response = {
//     status: number;
//     data: User[];  ← T became User[]
//     message: string;
// }

// So you can safely access:
console.log(response.data[0].name); // ✅ TypeScript knows: string
console.log(response.data[0].email); // ✅ TypeScript knows: string
console.log(response.data[0].id); // ✅ TypeScript knows: number

Step 4: Runtime Execution

// 1. apiClient calls fetch("/api/users")
// 2. Gets the JSON data
// 3. Returns it as ApiResponse
// 4. TypeScript's types are gone (runtime)
// 5. But we got type safety during development!
