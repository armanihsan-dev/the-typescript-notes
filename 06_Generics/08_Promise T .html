WHAT IS PROMISE<T>?

A COMPLETE GUIDE TO ASYNCHRONOUS TYPE SAFETY IN TYPESCRIPT

Part 1: The Mental Model & Core Idea

Definition

Promise<T> is a built-in generic type representing an eventual value of type T. It is used to type asynchronous actions that finish at some point in the future.

The Core Idea

// A Promise that will eventually resolve to a string
const promise: Promise<string> = new Promise((resolve) => {
    setTimeout(() => resolve("Hello"), 1000);
});

// A Promise that will eventually yield a User entity
const userPromise: Promise<User> = fetchUser();

Part 2: How Promise<T> Works

The Three Lifecycle States

State Meaning
Pending Initial state; asynchronous action is currently ongoing
Fulfilled Operation finished successfully → yields value of type T
Rejected Operation failed → yields an error/reason

Creating a Promise

// ✅ Create a Promise that resolves to a string
const promise1: Promise<string> = new Promise((resolve, reject) => {
    const success = true;
    if (success) {
        resolve("Success!"); // Fulfilled with string
    } else {
        reject(new Error("Failed!")); // Rejected with Error
    }
});

// ✅ Create a Promise that resolves to a number
const promise2: Promise<number> = new Promise((resolve) => {
    setTimeout(() => resolve(42), 1000);
});

// ✅ Create a Promise that resolves to an interface
interface User {
    id: number;
    name: string;
}

const promise3: Promise<User> = new Promise((resolve) => {
    resolve({ id: 1, name: "Alice" });
});

Part 3: Consuming Promises

1. .then() — Getting the Resolved Value

const promise: Promise<string> = new Promise((resolve) => {
    setTimeout(() => resolve("Hello World"), 1000);
});

// `.then()` callback param is strictly typed as string
promise.then((value) => {
    console.log(value); // "Hello World" (after 1 second)
    // value has type 'string'
});

2. .catch() — Handling Failures

const promise: Promise<string> = new Promise((resolve, reject) => {
    reject(new Error("Something went wrong"));
});

// `.catch()` captures the rejection reason
promise
    .then((value) => {
        console.log(value);
    })
    .catch((error) => {
        console.error(error.message); // "Something went wrong"
    });

3. .finally() — Guaranteed Execution

const promise: Promise<string> = new Promise((resolve) => {
    setTimeout(() => resolve("Done"), 1000);
});

promise
    .then((value) => console.log(value))
    .catch((error) => console.error(error))
    .finally(() => {
        console.log("Always runs, regardless of success or failure");
    });

Part 4: Chaining Promises & Type Propagation

The Mechanics: .then() Wraps Results in a New Promise 

// Each `.then()` transforms the resolved value and returns a new Promise
const promise: Promise<number> = Promise.resolve(5);

promise
    .then((num) => num * 2)        // Returns Promise<number>
    .then((num) => num.toString())   // Returns Promise<string>
    .then((str) => `Result: ${str}`) // Returns Promise<string>
    .then((result) => {
        console.log(result); // "Result: 10"
    });

Type Inference Flow Through Chains

const promise: Promise<number> = Promise.resolve(5);

// TypeScript automatically infers the return type across stages:
const chain = promise
    .then((num: number) => num * 2)        // → Promise<number>
    .then((num: number) => num.toString()) // → Promise<string>
    .then((str: string) => str.length);    // → Promise<number>

// Final inferred type: Promise<number>

Part 5: Real-World Scenarios

Example 1: Typed Fetch Request

interface User {
    id: number;
    name: string;
    email: string;
}

function fetchUser(id: number): Promise<User> {
    return fetch(`/api/users/${id}`)
        .then(response => response.json())
        .then(data => data as User);
}

// Usage
fetchUser(1)
    .then((user) => {
        console.log(user.name);  // ✅ Type-safe!
        console.log(user.email); // ✅ Type-safe!
    })
    .catch((error) => {
        console.error("Failed to fetch user:", error);
    });

Example 2: Dependent Sequential Requests

interface Post {
    id: number;
    title: string;
    body: string;
}

function fetchPosts(): Promise<Post[]> {
    return fetch("/api/posts")
        .then(response => response.json())
        .then(data => data as Post[]);
}

function fetchUserPosts(userId: number): Promise<Post[]> {
    return fetchUser(userId)
        .then((user) => fetch(`/api/users/${user.id}/posts`))
        .then((response) => response.json())
        .then((data) => data as Post[]);
}

// Usage
fetchUserPosts(1).then((posts) => {
    console.log(posts[0].title); // ✅ Fully typed!
});

Example 3: Concurrent Requests with Promise.all()

interface User {
    id: number;
    name: string;
}

interface Post {
    id: number;
    title: string;
}

const userPromise: Promise<User> = fetchUser(1);
const postsPromise: Promise<Post[]> = fetchPosts();

// Promise.all preserves tuple element typing: Promise<[User, Post[]]>
const combined: Promise<[User, Post[]]> = Promise.all([
    userPromise,
    postsPromise
]);

combined.then(([user, posts]) => {
    console.log(user.name);      // ✅ Type-safe User
    console.log(posts[0].title); // ✅ Type-safe Post
});

Example 4: async / await Syntax

// Async functions implicitly wrap return values in Promise<T>
async function getUserData(id: number): Promise<User> {
    const user = await fetchUser(id);
    // user is unwrapped to 'User'
    return user;
}

// Usage
const user = await getUserData(1);
console.log(user.name); // ✅ Type-safe!

Part 6: Advanced & Common Patterns

1. Custom Error Types in Rejections

interface ApiError {
    code: number;
    message: string;
}

function fetchData(): Promise<string> {
    return new Promise((resolve, reject) => {
        reject({ code: 404, message: "Not found" } as ApiError);
    });
}

fetchData()
    .then((data) => console.log(data))
    .catch((error: ApiError) => {
        console.log(`Error ${error.code}: ${error.message}`);
    });

2. Generic API Client

class ApiClient {
    get<T>(url: string): Promise<T> {
        return fetch(url)
            .then(response => response.json())
            .then(data => data as T);
    }

    post<T, U>(url: string, body: U): Promise<T> {
        return fetch(url, {
            method: "POST",
            headers: { "Content-Type": "application/json" },
            body: JSON.stringify(body)
        })
        .then(response => response.json())
        .then(data => data as T);
    }
}

// Usage
const api = new ApiClient();

interface User {
    id: number;
    name: string;
}

interface CreateUserPayload {
    name: string;
    email: string;
}

// GET request
const user = await api.get<User>("/users/1"); // Inferred: User

// POST request
const newUser = await api.post<User, CreateUserPayload>("/users", {
    name: "Alice",
    email: "alice@email.com"
}); // Inferred: User

3. Extracting Types via Awaited<T>

// Manual unwrapping using conditional types
type Resolved<T> = T extends Promise<infer U> ? U : never;

type UserPromise = Promise<{ name: string; age: number }>;
type UserType = Resolved<UserPromise>;
// Result: { name: string; age: number }

// ✅ Native built-in utility type (TypeScript 4.5+)
type UserType2 = Awaited<UserPromise>;
// Result: { name: string; age: number }

🎯 Key Takeaways

  • Future Value: Promise<T> explicitly conveys that an operation is asynchronous and guarantees that when fulfilled, the result matches type T.
  • 3 States: Operates across Pending, Fulfilled (yields T), and Rejected (yields an error reason).
  • Type Continuity in Chains: Every invocation of .then() wraps the return value into a fresh Promise, letting TypeScript automatically trace type conversions down the chain.
  • Async / Await Parity: await promise safely unpacks Promise<T> into a plain T type, matching standard synchronous type behaviors.
