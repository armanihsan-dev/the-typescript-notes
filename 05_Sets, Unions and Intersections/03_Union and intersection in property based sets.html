Part 1: The Foundation - Understanding the Universal Set

What is the Universal Set (U)?

The Universal Set is the set of ALL possible elements we're considering.

Part 4: Union of Sets (A ∪ B)

Definition

A ∪ B = { learners | learner satisfies A OR satisfies B }

Read as: "All learners who are in A, OR in B, OR in both"

What Can We GUARANTEE in the Union?

Let's check each property:

Property Guaranteed in A ∪ B? Why?
city = "Delhi"✅ YESBoth A and B require this. Every learner in either set has city = Delhi
age = 20❌ NOOnly set A requires this. Set B has no age condition
occupation = "student"❌ NOOnly set B requires this. Set A has no occupation condition
qualification = "B.Tech"❌ NOOnly set A has this. Set B has "BCA"
qualification = "BCA"❌ NOOnly set B has this. Set A has "B.Tech"

The Key Insight

┌─────────────────────────────────────────────────────────────────────┐
│                    UNION = BIGGER GROUP = FEWER GUARANTEES         │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  When we take the UNION of two sets:                              │
│  • The set becomes LARGER (more learners included)               │
│  • The guarantees become FEWER                                    │
│                                                                     │
│  WHY? Because in a union, we're including learners from BOTH     │
│  sets. A learner from Set A might not have Set B's conditions,   │
│  and vice versa. So the only things we can guarantee are the     │
│  properties that appear in BOTH original sets.                   │
│                                                                     │
│  "The only guarantee in a union is what's COMMON in both sets"  │
│                                                                     │
│  In this case: Only "city = Delhi" is common to both.            │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘

Example Learners in A ∪ B

  • ✅ Anas (20, Delhi, B.Tech, Engineer) → In A (satisfies A)
  • ✅ Maryam (22, Delhi, BCA, Student) → In B (satisfies B)
  • ✅ Sabaoon (20, Delhi, B.Tech, Student) → In BOTH (satisfies both)

All three are in A ∪ B, but they have different properties!

  • Anas is an Engineer (not a student)
  • Maryam is 22 (not 20)
  • Sabaoon has B.Tech (not BCA)
Conclusion

The union is DIVERSE. We can't guarantee much!

The Conflict: Qualification Mismatch

When we combine the conditions:

From A:

age = 20
city = "Delhi"
qualification = "B.Tech"   ← A's qualification

From B:

occupation = "student"
city = "Delhi"
qualification = "BCA"      ← B's qualification

Combined (for Intersection):

age = 20
occupation = "student"
city = "Delhi"
qualification = "B.Tech" AND qualification = "BCA"  ← CONFLICT!

Part 7: The Golden Rule (Explained)

The Core Insight

┌─────────────────────────────────────────────────────────────────────┐
│                    THE GOLDEN RULE                                  │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  UNION OF SETS = INTERSECTION OF GUARANTEES                        │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  A ∪ B → You can only guarantee what's COMMON to both       │   │
│  │  "More values allowed = Fewer guarantees"                   │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  INTERSECTION OF SETS = UNION OF GUARANTEES                        │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  A ∩ B → You can guarantee EVERYTHING from both sets        │   │
│  │  "Fewer values allowed = More guarantees"                   │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘

One-Line Summary

Union gives you more people but fewer guarantees (only what's common).
Intersection gives you fewer people but more guarantees (everything from both).

Part 2: The Golden Rule in TypeScript

The Exact Same Logic Applies!

┌─────────────────────────────────────────────────────────────────────┐
│                    GOLDEN RULE IN TYPESCRIPT                       │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  UNION (|) = MORE values allowed = FEWER guarantees              │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  type A = { name: string; age: number };                  │   │
│  │  type B = { name: string; city: string };                 │   │
│  │                                                             │   │
│  │  type Union = A | B;                                       │   │
│  │                                                             │   │
│  │  ✅ You can GUARANTEE: only what's COMMON                 │   │
│  │  → name: string (present in BOTH)                        │   │
│  │                                                             │   │
│  │  ❌ You CANNOT guarantee:                                  │   │
│  │  → age: number (only in A)                                │   │
│  │  → city: string (only in B)                               │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  INTERSECTION (&) = FEWER values allowed = MORE guarantees        │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  type Intersection = A & B;                                 │   │
│  │                                                             │   │
│  │  ✅ You CAN guarantee EVERYTHING:                          │   │
│  │  → name: string                                            │   │
│  │  → age: number                                             │   │
│  │  → city: string                                            │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘

Example 1: API Responses (The Classic)

// Set A: Success Response
type SuccessResponse = {
    status: "success";
    data: { id: number; name: string };
    timestamp: string;
};

// Set B: Error Response
type ErrorResponse = {
    status: "error";
    error: string;
    code: number;
};

// UNION: The API can return EITHER
type APIResponse = SuccessResponse | ErrorResponse;

// What can we GUARANTEE about APIResponse?
// ✅ status: "success" | "error" (from BOTH)
// ❌ data (only in Success)
// ❌ error (only in Error)
// ❌ code (only in Error)
// ❌ timestamp (only in Success)

// So TypeScript forces us to CHECK before using!
function handleResponse(response: APIResponse) {
    // ❌ Can't access data directly
    // console.log(response.data); // ERROR!
    
    // ✅ Must check first (narrow the type)
    if (response.status === "success") {
        console.log(response.data); // ✅ Now we KNOW it's a Success
    } else {
        console.log(response.error); // ✅ Now we KNOW it's an Error
    }
}

The Golden Rule in Action: The union (|) gives us fewer guarantees, so TypeScript forces us to check before accessing properties that aren't guaranteed.

Example 2: User Types

// Set A: Guest User
type Guest = {
    role: "guest";
    name: string;
};

// Set B: Logged-in User
type LoggedInUser = {
    role: "user";
    name: string;
    email: string;
    preferences: { theme: string };
};

// Set C: Admin User
type Admin = {
    role: "admin";
    name: string;
    email: string;
    permissions: string[];
};

// UNION: A user can be ANY of these
type User = Guest | LoggedInUser | Admin;

// What can we GUARANTEE about any User?
// ✅ role: "guest" | "user" | "admin" (from ALL types)
// ✅ name: string (from ALL types)
// ❌ email (only in LoggedInUser and Admin)
// ❌ preferences (only in LoggedInUser)
// ❌ permissions (only in Admin)

// TypeScript forces us to check:
function greetUser(user: User) {
    console.log(`Hello ${user.name}`); // ✅ Guaranteed!
    
    // ❌ Can't access email directly
    // console.log(user.email); // ERROR!
    
    // ✅ Must check first
    if (user.role === "admin" || user.role === "user") {
        console.log(user.email); // ✅ Now we KNOW it exists
    }
    
    if (user.role === "admin") {
        console.log(user.permissions); // ✅ Now we KNOW it's an Admin
    }
}

Example 3: Form Data (Union for Different States)

// Set A: Form is empty
type EmptyForm = {
    status: "empty";
};

// Set B: Form is being filled
type FillingForm = {
    status: "filling";
    data: { name: string; email: string };
    progress: number;
};

// Set C: Form is submitted
type SubmittedForm = {
    status: "submitted";
    data: { name: string; email: string };
    submissionId: string;
};

// UNION: Form can be in ANY state
type FormState = EmptyForm | FillingForm | SubmittedForm;

// The Golden Rule:
// UNION = MORE states = FEWER guarantees
// We can only guarantee: status exists
// Everything else must be checked!

function processForm(form: FormState) {
    switch (form.status) {
        case "empty":
            console.log("Form is empty"); // ✅ Guaranteed
            break;
        case "filling":
            console.log(`Progress: ${form.progress}%`); // ✅ Now we KNOW it's Filling
            break;
        case "submitted":
            console.log(`ID: ${form.submissionId}`); // ✅ Now we KNOW it's Submitted
            break;
    }
}

Part 4: Intersection in TypeScript (The "AND" Type)

Example 1: Combining Features

// Set A: Has a name
type HasName = {
    name: string;
};

// Set B: Has an age
type HasAge = {
    age: number;
};

// Set C: Has an email
type HasEmail = {
    email: string;
};

// INTERSECTION: Must have ALL of these
type Person = HasName & HasAge & HasEmail;

// The Golden Rule:
// INTERSECTION = FEWER values = MORE guarantees
// We can guarantee EVERY property!

const person: Person = {
    name: "Alice",
    age: 25,
    email: "alice@email.com"
};

function processPerson(person: Person) {
    console.log(person.name);  // ✅ Guaranteed
    console.log(person.age);   // ✅ Guaranteed
    console.log(person.email); // ✅ Guaranteed
    // No checks needed! We KNOW everything exists!
}

Part 5: The "Guarantees" Concept in Practice

What TypeScript Does With These Guarantees

type A = { name: string; age: number };
type B = { name: string; city: string };

// UNION: Fewer guarantees
type Union = A | B;

let value: Union = { name: "Alice", age: 25 };

// ✅ Allowed: Guaranteed properties
console.log(value.name); // ✅ Works (guaranteed in both)

// ❌ Error: Not guaranteed
console.log(value.age);  // ❌ Error! (might be B)
console.log(value.city); // ❌ Error! (might be A)


// INTERSECTION: More guarantees
type Intersection = A & B;

let value2: Intersection = {
    name: "Alice",
    age: 25,
    city: "Delhi"
};

// ✅ Allowed: Everything is guaranteed!
console.log(value2.name); // ✅ Works
console.log(value2.age);  // ✅ Works
console.log(value2.city); // ✅ Works
